## P0：元素点击回执 completed，但点击位置偏移，输入框未聚焦

Run：`run-1791012839158-29dba451-2ca`，日志位于 `runs/local/a-line-test-20261003/<Run>/trajectory.jsonl`。使用仓库现有 `packages/computer-cua/src/fixtures/managed-dom-fixture.html`，仅本机 HTTP 服务。新临时受管 Chrome，起始 URL `http://127.0.0.1:4318/fixture`。目标：点击 Search，输入合成标记 `A-LINE-FOCUS-001`，核对值，不导航、不提交。

预期：Search 输入框获得真实键盘焦点，再输入标记。实际：一次最小 drag 后模型连续五次 `click_element` 对准有效 DOM Search 引用；每次回执 completed，后续 DOM `state.focused=false`，截图仍是空 Search，指针落在 Continue 附近。没有任何 type 调用，没有假定输入成功。该运行由测试方主动取消，不是自然失败。

关键证据：

- 初始截图 viewport 为 1568×1181；Search 的物理 bbox 约 x10.45/y203.80/w192.08/h28.09，中心约106.49/217.84。
- 初始模型 drag 源点106/216，Host 送给驱动的 window-pixel 为81/165，驱动报告 screen62/138。出现两层比例收缩迹象，需核查坐标单位；不能仅从回执宣称实际点击落点正确。
- 07:35:52、07:36:07、07:36:27、07:37:47、07:38:15 UTC 的 DOM 点击均 completed，之后 Search focused 均 false。
- 第一张有 DOM 的观察 07:35:40 UTC 为 UIA26/DOM8；标签、bbox及元素 ref 完整，不是每次缺引用。
- 故障截图 `assets/screenshots/4b7621f9-8252-48c2-a5e5-f17df519dad1.png`；纯合成内容，可用于复验。

初步原因（待修复方确认）：`cua-driver-computer.ts` 中 mapWindowPoint 将截图坐标缩放为窗口 bounds，再由 CUA 0.22.2 foreground action 二次转换。需核对该版本 window-pixel 是截图像素、窗口逻辑点还是屏幕物理像素，同时审查 DOM、UIA、drag/click 的单位一致性。不可用取消焦点检查、程序化 type 或未知副作用重放掩盖问题。

验收：同一 fixture，至少5次新窗口运行，Search 点击后 DOM focused=true、输入值逐字一致、地址栏与Continue不受影响。另测非1:1截图/窗口比例和正确点击拒绝边界。不要只靠 mocked completed 收据。
