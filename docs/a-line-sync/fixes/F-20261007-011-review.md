## 独立反例与实现边界

独立测试验证：fetch 与 body 忽略 Abort 且永不 resolve 仍在单次总 deadline 返回 nonretryable feedback timeout；body timeout 保留已收到 HTTP status；迟到 headers 不触发 json；迟到 body 不修改 settled failure 的诊断；超时之后真正 reject 的 transport promise 被观察，没有 unhandledRejection；Run Abort 的 null 原因保持 null；toJSON 触发取消或跨 deadline 时零 fetch；timer 尚未交付但 fetch/body resolve 越过单调截止时拒绝；fetch_invoked 回调取消阻止真实 fetch；headers_received 回调取消阻止 json。这些通过分支使用 fake timer、注入 response/deferred promise 及 performance.now spy。

单一 timeout 覆盖序列化、fetch 和 body，本地取消来源先锁定，再向请求 signal 发送 Abort；不能因随后 Run cancellation 覆盖先到 timeout，也不能把先到 Run cancellation 改写成 timeout。原始 Run reason 保持对象身份或 primitive 值，不用 nullish fallback 换成别的错误。request timeout 继续 retryable:false/retryMode:feedback，未知远端结果不自动重发。

本地 promise settle 不证明真实远端工作已停止。JS timer 无法抢占同步阻塞代码；post-await 和序列化后 monotonic 检查只确保恢复到 JS 时不会接受过期结果。晚 promise 必须保持已观察拒绝，不能因此重启 request、继续读取 body 或追加成功诊断。完整 body 证据与返回前取消合同分别记录，不能把开始请求当实际 HTTP 完成。
