## 下一阶段：可信原生能力最小方案

优先建议扩展现有CUA原生驱动，新增版本化、只读、精确目标绑定的拓扑接口；不是自动升级已部署版本，也不是把旧list_windows补complete。另一选择是独立打包helper，代价是新的构建、签名、TCC身份与维护。

最小生产拆分：

1. 原生producer接收已授权目标pid/window_id。CG全层可见数字快照A → 仅目标AX窗口及其附属sheet/menu关系 → CG快照B。只采身份、层级、z、几何、可见性、AXrole/subrole/父子或modal关系；不采标题、value、正文、截图，不遍历无关应用AX。
2. 合同明确scope、schema/producer版本、时间/采样generation、枚举成功或失败、raw/retained/skipped计数、逐项AX查询success/unsupported/error、精确关联边。unknown不能伪造为false/absent；任何失败、无法归属新窗、身份变化/权限拒绝/截断/解析丢行均不可证明完整。双快照是稳定性证据，不宣称原子性，仍保留逐动作前台守卫。
3. Harness新增macOS专属target-scoped source/能力协商与严格解析，不能冒用win32_relationship_probe complete。只在明确范围可信时继续；精确owned-child另走既有Surface授权。跨进程保存面板或未知owner不能同PID猜关联，必要时要求用户明确选择并重新核身份。
4. 未提供该RPC/可信producer时能力明确unsupported，在输入前报告原因，不静默关闭探测。producer只读诊断与执行会话隔离，不重用过期元素token/窗口ID。

必要验收：普通窗无变化；真实附属sheet/menu；无关窗口；同PID无owner；跨进程保存面板；CG失败/丢行；AX拒绝/截断；窗口消失/ID重用；采样竞态；多显示器/Space。负例零越权、零重放、清晰unknown，Windows不回归；正例最终须原六行UTF8输入、保存、重开逐字核对，不能代做成果或降低目标。
