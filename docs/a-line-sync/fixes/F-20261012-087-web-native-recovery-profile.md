# F087 — Host-owned native document tasks from Web

The Web client could start a single window or browser task but could not select the exact two-window recovery and single saved-document grant needed to close and reopen a local document. An optional Host startup profile now supplies those identities and the one file; Web sends only its opaque profile ID. Ordinary Run configuration remains unchanged.

The profile is consumed once before asynchronous start work; same-command retries return the original result, and failure or unknown outcome does not restore the permit. Host, Runtime API and Relay accept only the exact native selector and reject client paths, process/window handles, extra fields, and either switchWindows boolean. Existing native focus, application/document proof, cleanup and one-dispatch rules remain in force. The Web view exposes loading, failure, expiry and refresh states for its existing discovery deadline.

Validation: Sol's original five-file focused run passed 128 tests, the changed Home suite passed 26 tests, the three Relay routing/server suites passed 14 tests, TypeScript build and Web production build exited 0. Root independently checked strict schema, refresh/expiry and real Relay forwarding/no-forwarding. Private supervision passed Node18/Python7 and exact dependency fingerprints.

A real local Host/Relay/native diagnostic (offline Provider, no real model HTTP) saved its unique 37-byte Chinese/emoji file, closed once, recovered only the preselected blank, reopened once to a new exact document, captured fresh content, and completed an ordinary action: seq168 succeeded, 13/13 actions, cleanup/errors empty. Sol/Root viewed the final PNG and verified disk/AX format. The initial pre-Run Relay400 failure is retained and explains the additional Relay schema fix.
