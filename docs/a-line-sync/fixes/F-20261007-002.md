## 接收的问题与事实边界

接收 [I-20261007-002](../issues/I-20261007-002.md)。在正式生产 Run 的 `Computer.open` 中，foreground 模式对精确 PID/HWND 发起一次 `bring_to_front` 后，现有独立焦点证明未通过；Run 在任何窗口 capture、Provider/API、GUI 输入或审批前失败，清理后 lease 已释放。driver 返回的可见错误只报告目标及 `observed foreground window_id=1312` 相同，没有持久原始结构化字段。

源码 `window-contract.ts` 已核明：同 HWND 仍会因 `focused_window_id` 不符、`frontmost_ordinary_window_id` 不符或 `exact_window_effect.verified === false` 被拒；human-readable message 当前用 `focused ?? frontmost`，因此可能遮住具体是哪项触发。此次拒绝不能归因到进程前台、驱动校验、模态/拓扑或时序中的某一种；不猜 front PID、AX 状态或 driver 内部原因。外层再执行一次公开 Raise 未改变结果；不增加 activation 重试。

## 最小诊断方案（不改变准入）

保持 `activateWindowTarget` 的现有成功判据、拒绝表达式、错误分类、`bring_to_front` 次数、open cleanup、0 capture/input/API 行为完全不变。只为拒绝/unknown 错误附加定长 ASCII 白名单 summary，使其经过 `CuaDriverComputer.open` 的 normalize 包装后仍能由 Runtime error 事件看到。

投影字段为固定 key 和 enum：

- `branch`: `is_error | degraded | explicit_mismatch | unverified`
- `status`: `activated | partial | refused | missing | invalid`
- `window_id`, `focused`, `frontmost`, `target_hwnd`, `now_fg_hwnd`: 相对请求 target 的 `match | mismatch | missing | invalid`；在 safe integer / 十六进制安全解析后可附归一化数字，不透传原字符串。零句柄在诊断中为 `invalid`，不改变当前 admission parser/行为。
- `front_process`, `exact_verified`, `landed`: `true | false | missing | invalid`
- `exact_effect`: `present | missing | invalid`
- `reason`: 仅表示现有 gate predicate 命中事实，如 `frontmost_mismatch`、`exact_verified_false`、`focused_mismatch`、`explicit_mismatch`、`modern_proof_missing`、`degraded` 或 `driver_refused`；不声称 driver 内部原因。

`isError/degraded` 只编码布尔值。summary 不含 PID/HWND 原值、任意 status/raw field、session、标题、窗口内容、AX、result text、structured JSON、URL、异常原文或任意嵌套对象。保留原有 “no capture or input was sent” 安全声明。任何未知类型按 `invalid`，未出现按 `missing`，不得将缺字段标为 unsupported 或自动补真值。
