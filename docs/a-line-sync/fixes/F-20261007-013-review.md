## Security 与 CF 边界

只读本地 Apple SDK 的 SecCode.h、SecStaticCode.h 及锁定 security-framework 3.7.0、core-foundation 0.10.1 wrapper；没有执行这些原生 API。SecCode::for_self 取得 dynamic self code，check_validity 使用固定 identifier requirement 与 STRICT_VALIDATE|NO_NETWORK_ACCESS，在 CopySigningInformation 前及提取磁盘相关数据后检查。

SDK 明确 CopySigningInformation 成功本身不保证已签名或数据有效；unsigned 可能返回无 identifier 的字典，必须先 validity 检查。kSecCodeInfoPList 是代码签名所见 secured plist，不是 CFBundle 可变字典；MainExecutable 是 CFURL，Unique 是 CFData。native 实现采用 null check、dictionary.find 和 CFType.downcast，避免 missing field、错误 type 或 null 直接 typed wrap；成功 Copy 的字典持有 Create-rule，字典内值走 Get-rule retain。
