F010 已验证发布文件清单，但生产普通入口没有调用它。本批增加必须提供独立 manifest 与固定 digest 的启动入口，避免把一次人工检查当成每次启动默认保护。候选发布目录外的受控 bootstrap 和 checker 由协调方冻结；候选自身重新生成 hash 不能成为信任根。

## 实施合同

唯一 Sol medium 作者增加 scripts/relay-verified-start.mjs、对应测试与必要说明，另一 Sol medium 独审。CLI 只接受必需 releaseRoot、manifestPath 和 pinPath，拒绝缺失、重复、多余参数；不接受自定义 entry 或 CLI importer。两个外部文件须在候选根目录之外，读取有大小上限、拒绝符号链接与异常文件，错误固定脱敏。

外部 pin 沿用 F010 的规范化 manifest SHA256，即 serializeRelayManifest(parsedManifest) 的摘要，不是原始 JSON 字节摘要；固定为 lowercase 64 hex 和可选一个 LF（最多65字节），不可自行生成。manifest 最多64KiB，严格解析后把外部 pin 直接交 F010，只有 result 为 bytes_and_layout_match 才继续。pretty JSON 或合法键顺序变化不改变规范化 pin 的语义。只有全部发布文件和布局验证通过、根身份复核未漂移后，才动态导入固定 apps/relay/dist/index.js。测试通过注入 fake importer 断言错误零导入、正常恰一次；测试不导入真实服务，不读私有配置或 listen。

bootstrap/checker 位于受控候选外，不新增候选 profile 资产。部署责任方必须固定这两个脚本及外部清单/pin 的可信来源，并保证 release 不可变、服务用户无写权限和独占切换；仅重复 hash 或声明参数不能消除验证到 import 的竞态。

## 验收边界

通过仅称 point-in-time release files 已核与 entry import requested，不称进程健康、服务已监听或运行进程 attested。Relay 原 index 的异步 main 不因 dynamic import resolve 而变成健康证明。普通生产启动路径、本批源码、真正部署和健康检查分别签收。

唯一作者已实现启动脚本、12项假接口测试和启动说明。作者第一次12项中11通过、1失败为测试自身 file URL pathname 百分号编码处理，改用 fileURLToPath 后12通过；实现未因该测试修正改动。独审13反例通过，随后作者将独测持久化仅改两行 import，独审在正常路径实际25/25（作者12+独13），duration737.162917ms，3项syntax exit0，四资产及F010 checker前后hash一致。
