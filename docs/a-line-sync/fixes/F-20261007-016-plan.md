## Core 与生命周期

Ops 最小边界：monotonic_now、spawn_fixed、poll_receipt、observe_child_no_reap、capture_identity、term_audittoken、reap_exact、close_owned。状态为 prepared、spawned/observing、terminating、exited/reaped、pending_keeper；无 PID kill、KILL、fork、daemon、自动重启 API。每次最多一个 child。

父进程是独立单 waiter，SIGCHLD=SIG_DFL 且无 SA_NOCLDWAIT，无其他 wait/reaper。用 `waitid(P_PID, child_pid, ..., WEXITED|WNOHANG|WNOWAIT)` 观察退出而不提前 reap。保持未 reap child 才具有 PID 不复用前提。SIGINT/SIGTERM handler 只设置 `sig_atomic_t` cancel，走同一 cleanup 状态机，不退出遗失 child；处理 SIGPIPE，报告 EPIPE 不得杀掉 keeper。

spawn 一次：argv 固定为 `[canonicalChild, "diagnostic-preflight-only", NULL]`。父端 pipe 非阻塞。取得 kernel identity：`task_name_for_pid(mach_task_self(), child_pid, &port)`，`task_info(TASK_AUDIT_TOKEN)` 核对 count；token PID=spawn PID、有效 UID=受控预期、pidversion 真实来自 kernel；`proc_pidpath_audittoken` 对照 canonical child。释放 Mach port。任何错误均非 pass；不得手造 token、从 caller 字符串或 LOCAL_PEERTOKEN 推导完整绑定。绑定一次，不能重新绑定新 exec 来追杀。

先/随后检查 WNOWAIT：token 获取前 child 已自然退出时，不再获取 token 或发信号；有限 tail drain 后准确 reap，依据 receipt+exit 分类，但不补称 runtime 身份/TCC 已证明。检查期间退出也先走退出分支。只有仍属原 child 且绑定有效才允许 token signal。

从 spawn 调用前开始 monotonic 30 秒观察期限，覆盖 spawn 返回、身份绑定、receipt；每次操作返回后重新检查 deadline/cancel，首次 timeout/cancel/invalid 判定锁定，迟到成功不得复活。同步 Security/Mach/kernel 调用无法硬抢占，卡住时仅在恢复后判定超时，不承诺总进程 35 秒结束。

需清理时最多一次 `proc_signal_with_audittoken(&originalToken, SIGTERM)`；副作用前先锁存 term_attempted，errno/重入/中断不能重试。该 API 返回 errno 整数或 0。禁用可升级 SIGKILL 的 proc_terminate_with_audittoken；无 PID fallback。信号后最多另观察 5 秒，signal success/ESRCH/pipe EOF 均不是 exit 证据。

观察到准确退出后才 `waitpid(exact_child_pid, ...)` reap；EINTR 可继续等待同一个未完成的 reap，不得重复已成功 reap；成功 latch 后绝不 signal。WNOWAIT 已证退出时，最多两个 bounded tail 轮次，不能因 descendant 持有 pipe 不 EOF 而无限延迟 reap；未闭合 receipt 拒绝并关闭自有 FD。ECHILD 或归属丢失进入 ownership_unknown keeper，不再 signal/reap，不谎称仍保有准确 child ownership。

活 child 无 token、身份漂移、或 TERM 后未证退出时进入 pending_keeper；维持 supervisor、child 归属（若仍成立）、资源/lease，不释放、不另起 launcher、不重放。仅 bounded discard drain 和观察等待；自然退出可准确 reap。报告 ownership_unknown 与 retained-child pending 必须分开。需要人工介入由（10）重新获取 OS 身份证据后处理，不给猜 PID/broad kill 指令。父 SIGKILL、崩溃、掉电无法保证 keeper 存续，明确属于受控外部运维边界。

## Receipt、输出及退出分类

仅接受 F013 实际 serde canonical 字节：固定顺序七字段 `schema,outcome,selfIdentityValidated,accessibility,screenCapture,principalVerified,readyForDispatch`，一条 JSON + 一个 LF。schema=`harness.diagnostic_preflight.v1`，末两字段永远 false。用固定 13 个字符串模板，不引入宽松 JSON parser：

- self=true，AX/SR 各 true/false/null 九种；TT 对应 observed_unverified/exit0；其余均为 bool 对应 permissions_not_granted/exit2；存在 null 对应 permission_status_unknown/exit2。
- self=false，AX/SR=null；identity_unknown、identity_rejected、report_unknown 对应 exit2；invalid_arguments 对应 exit64。

stdout 总接收上限 1024 bytes（含 LF），每轮每 pipe 最多读取 256 bytes，公平轮转并重查时钟/取消。超限、额外数据/帧/字段/空白、未知编码或模板均拒绝。stderr 必须为空，任意一个 byte 即 stderr_present；不存储/回显原文，只固定错误码和有界计数。拒绝后仍有限 discard，避免背压阻止 child 退出；不落原始 stdout/stderr，缓冲用后清理。

完整结果须 receipt 与 WIFEXITED 的准确 code 一致。信号退出算 interrupted，不因已有 JSON 算成功。超时/cancel 后的 exit0/合法 receipt 只能证明清理，不恢复成功。stdout EOF 不能替代退出，反之 child 已退出但输出未闭合不能算合法 receipt。正常最大结果为 preflight_observed_unverified 或 known_refusal，不输出 permissions_pass/TCC_verified/ready_for_dispatch。

supervisor 对外报告也须固定常量、有界非阻塞写；不回显 path、任意 errno message 或候选输出。读者关闭、EPIPE/输出满仅丢报告，不退出遗失 keeper。pending 的资源/lease 归属写入（10）事件交接，不因 CLI 上层超时或通知发送成功自动释放。

### 首版独立反例后的必要澄清

F016 首版作者11组通过，独立16组实际14通过/2失败：reap Ops同步重入和持续EINTR无界。历史合同中的“最多一次成功reap”不能允许无限未完成尝试。回修须以全step in-flight锁拒绝同实例同步重入，副作用调用前置锁存；同一退出证据后的reap最多8次EINTR，耗尽进入专用 `incomplete_reap_keeper`，不得借普通pending再次观察退出后重新reap。该状态停止signal/reap、保留资源和lease且不报告released。作者和独立反例对回修新指纹通过前，不交native compile；首版通过数不能抵销失败。

incomplete-reap已有WNOWAIT的退出证据，缺的是回收确认，不能笼统报告为仍活child，也不对已退出child发TERM。它与活child/token缺失的pending、ECHILD的ownership_unknown必须分开。长期停留时由（10）记录精确supervisor身份、此前child身份、退出证据和未回收状态；新鲜只读核当前OS状态/所有权后，另行审定父监督器收尾及OS接管回收步骤。本文不预授权停止父进程、不以旧PID猜测对象；OS接管也须实际核不存在/已回收后才release，不因人工操作发出就宣告清理成功。没有该运维后备时可以完成fake/compile，但不能据此放行真实启动。
