## 根因与边界

固定F028源码可达链：canonical registry在manifest存在时进入private_observation；Standard的免提示早返回仅限无manifest；新Tool/Probe没有protected_resource_scope，参数又没有PID/window_id/browser target，最终误落display fallback。最小registry没有get_screen_size，因而该路径生成display identity unavailable。此为主、作者、独立审查和T070分别确认的源码路径；没有重新打印运行时ToolResult，不冒称捕获了运行时错误码。

不是AX/TCC或API超时。生产一次性入口目前只用standard+私有policy且禁止manifest环境，走无manifest路径，不能把测试失败直接认定默认入口也失败。但manifest资源合同确实缺失；仅给测试补屏幕工具、桌面grant或删除合法正控均不解决问题。既有application资源先要求PID，不能用假PID或提前OS查询填充bootstrap。

## 最小修复

1. `cua-driver-core/src/tool.rs`：仅精确新Tool与固定TextEdit bundle构造三字段资源：kind=textedit_identity_candidate、bundle_id=com.apple.TextEdit、operation=discover_textedit_window_identity。不查询OS、不伪造PID、不增加display工具，不接受调用者注入资源，仍经原grant授权。
2. `cua-driver-core/src/session_manifest.rs`：新增严格bool字段`resources.textedit_identity`，默认false。仅private_observation匹配精确三字段资源，必须同时资源true且对应Tool决策Allow；显式deny与未声明不通行。旧application/window/display/input分支不放宽。

合法session manifest示例（不是私有policy.yaml的新语法，也不是增加CLI manifest入口）：

```yaml
version: 3
allow:
  tools: [discover_textedit_window_identity]
resources:
  textedit_identity: true
```

Standard无manifest的原行为不变。资源身份许可不授权输入/捕获/后续窗口操作；原两RPC、native producer、隔离host/main、三个镜像、Cargo.lock与features/依赖均未改。
