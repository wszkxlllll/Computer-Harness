`request` 的 connect listener 只检查 settled 和 Abort，没有单次发送锁。修正应在首次 write 前占位；再次 connect 不得重发。仅使用 once listener 也必须保持 Abort 与已写出但未知结果的边界。作者已收到反例，等待重新冻结。

## 协议与证据范围

固定原生源码 `cua-driver-core/src/daemon.rs` 和 `cua-driver/src/serve.rs` 使用按行分隔的 daemon JSON：`metadata` 与 `call/check_permissions`，响应为 `{ok:true,result:...}`，没有 request ID。这里不采用 `core/protocol.rs` 的外层 MCP JSONRPC。客户端各请求使用一个新连接，先后执行，并固定 `prompt:false`、`probe_direct_capture:false`；不提供任意工具参数、重试或派发入口。

权限结果位于 `result.structuredContent`，AX 与 SR 对应 `accessibility`、`screen_recording`。原生只读检查不请求权限、不运行直接捕获能力 probe；明确 null/not_checked 的投影只说明该回复自报未 probe。PID、PPID 和 executable 匹配仍是服务端自报。bundle 路径和责任环境变量的 source 归类不是完整 TCC 责任链证明，也不是系统设置中具体授权项目的证明。

fs 的 parent realpath、lstat、uid、mode、dev 与 ino 检查能发现观察时刻的身份变化，不能原子绑定已连接 peer 或排除检查之间替换后恢复。无 peer 认证、进程启动身份或 executable hash。本次未把 fs 前后相同、权限 true 或 source 为 driver-daemon 写成安全 pass。

parser 最多接收 65536 字节含 newline，以 fatal UTF8 解码；同次接收含多个帧即拒绝。首完整帧后调用 destroy 并忽略迟事件，不证明未来字节不存在，也不证明服务端已终止操作。destroy 是关闭请求，fixture 调用计数不是真实 OS close 验证。README 已明确此边界及请求可能产生 daemon 聚合遥测。

## 生命周期与后续边界

默认 performance.now 提供单调时钟，30 秒总预算覆盖文件检查和两个请求，Abort 后迟到文件结果不能再连接。JavaScript timer 不能抢占阻塞同步调用，发送到服务端的请求也不能因客户端关闭而宣称执行已经终止。F009 不调用 spawn、TERM、shutdown、dispatch 或 F008 token。

未来精确 TERM 需要另审可信 OS 身份机制。同步核 PID/start/exe 再 kill(pid) 仍存在复用竞态。本机 SDK 声明 `proc_signal_with_audittoken` 仅说明有候选 API，不证明可信 token 已取得或当前系统内核行为已经验证；F009 未实现或调用它。不使用名称相近但可能选择其他信号的 terminate API 冒充只发 TERM。

本轮所有执行均为 Node 语法及合成 fixture，没有连接真实 socket 或 mock server，没有 SDK、native、GUI、capture/input、模型/API、进程查询或信号、unlink、TCC、构建和 Git 操作。I002、真实权限归属、F008 adapter 及新的现场诊断仍待后续证据。
