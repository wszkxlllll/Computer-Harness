# F-20261012-089: Optional finish results bound to retained observations

The earlier T1 Run read Mac mini source evidence as M6 but finished with M4. This change adds an explicit `source-linked-finish-v1` output contract. When enabled, the model supplies references to retained elements in the same Run's committed Observations; Runtime renders the main result from those elements. The model's free-form summary remains separately labelled `reportedSummary` for audit.

Contracts contain at most 32 named fields. Each result field supplies source references, an explicitly unverified inference, or an unknown reason. References must resolve uniquely before the finish response and match the Run, Observation, computer session and Surface. Runtime uses the persisted grounding subset, not Memory narration or an evicted full catalog. It preserves source text, selected/disabled state, options and capture time; it does not decide whether a source semantically answers the field or establishes a lowest-price standard configuration. Multiple sources remain available for independent review.

Canonical output has explicit UTF-8 size limits. Empty results, missing required fields, forged values, inconsistent identities and over-limit excerpts fail before completion; text is not silently sliced. Malformed model evidence is normalized before event persistence, so rejection leaves a readable failed trajectory. Ordinary tasks ignore unsolicited evidence and retain their existing finish behavior. Pause, correction and cancellation continue to take precedence at the existing finish command barrier.

The feature is off by default. The normal CLI accepts `--source-linked-finish-contract <json>`; Host accepts the same bounded JSON through `HARNESS_SOURCE_LINKED_FINISH_CONTRACT`. Invalid configuration fails before Run assembly. Host configuration applies to that explicitly configured session; existing services do not acquire the feature without a new configuration and restart.

Validation on the frozen source: the author ran 10 test files, 452 tests, and the affected project TypeScript build successfully. Sol independently ran eight complete files, 239 tests; Root independently ran Runtime and RunFactory, 213 tests. These independent groups total 452 tests. The SDK integration uses the normal RunFactory and DefaultContextCompiler and replays the persisted canonical result, preserving M6 and false state flags while retaining the model's M4 only as its audit summary. Negative cases cover unavailable or foreign references, size limits, malformed reports, default compatibility and control commands. The first SDK fixture Provider-id mismatch is retained in the private author receipt; it failed before a Run or Provider call.

No new real Provider request, GUI task or T1 business Run was performed for this fix. Source/output consistency is the verified scope; T1 business accuracy and the separate T3 workflow remain unverified. See [Sol review](../../astra-source-linked-finish-review-2026-10-12.md).
