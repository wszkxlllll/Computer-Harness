# F-20261011-072: exact macOS attached-sheet lifecycle

TextEdit exposes its Save sheet as a separate CGWindowID. Parent-only capture now correctly excludes the sheet, but the model continued sending input to the parent. This change lets the existing SurfaceRegistry push/pop follow a uniquely proven attached sheet when opened-window switching is explicitly enabled.

The native `get_window_state` response adds private, versioned `attached_sheet_proof`. A successful complete read of the exact parent’s direct AXChildren must contain exactly one AXSheet, whose AXParent is CFEqual to the retained parent. For a nested AXSheet parent, its direct AXWindow ancestor is also bound and revalidated through fresh AXWindows membership and direct-child CFEqual checks. When the ordinary catalog is unresolved, a separately registered relation snapshot is returned alongside the still-degraded/incomplete catalog; the adapter accepts only that exact relation snapshot and never upgrades catalog completeness. Direct native window IDs, AX PIDs, WindowServer owners, positive AX/CG geometry, frontmost PID, and focused child are checked again before publishing the proof. A successful no-sheet read also requires the exact parent focused. Any read failure, unclassifiable child role, ambiguity, identity/geometry change, or stale focus yields no proof.

The exact-foreground, unaddressed macOS hotkey route now uses the existing guarded foreground HID activation and global key dispatch. This fixes the TextEdit Save-panel case where the PID-routed menu shortcut returned a completed receipt while the Save panel ignored CMD+SHIFT+G. Background and other existing hotkey routes remain unchanged; an exact-focus guard failure still sends no key events.

The TS consumer matches the proof against the current parent baseline and the unique visible new row in the actual partial macOS inventory. It preserves `complete=false`, requires foreground delivery and `opened-windows-v1`, and uses the existing child push/pop and reference invalidation. The new admission source is limited to a native window with a parent across Protocol, Runtime and Trajectory. No production Guard or global inventory completeness rule is relaxed. Same PID, a title, or a newly appearing window alone never authorizes switching.
