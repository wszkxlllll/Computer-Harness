## 结论

现有官方CUA现场接口没有给出可用的PID/CGID（测试方T0465），F026两项RPC又要求先绑定精确身份，形成工程上的首次发现缺口。可有条件新增显式TextEdit-only身份发现能力；不能把它暗中加入既有两RPC白名单，不能把target改成可选或绕过现有焦点保护。

本轮Astra medium协调、6.1 Sol medium调研、独立6.1 Sol medium审查；主代理读取固定源码和T0465/T0466核对。仅新增本文，没有源码/补丁/依赖/构建/服务/GUI/TCC/API变更，没有新冻结产物，没有运行任何原生发现。AX是否已信任仍未知，不从签名或接口缺失推断。

## 可复用与不可复用的证据

源码根为F026固定源的`libs/cua-driver/rust`：

- `crates/platform-macos/src/apps/nsworkspace.rs:327`已有`NSRunningApplication::runningApplicationsWithBundleIdentifier`限定bundle查询。可参照底层调用，不能复用launch流程或后续find/reconciliation选择来证明唯一。
- `apps/mod.rs:658`的bundle_id_for_pid提供反向bundle核对思路；不得调用读应用名称或shell ps的helper。
- `tools/list_apps.rs`会扫描其他应用及路径，`tools/list_windows.rs`先全局枚举标题再按pid过滤，两者都不满足本范围。
- `ax/bindings.rs`的focused_window_id_of_pid只给焦点映射，不证明唯一普通根或owner；copy_ax_windows的失败为空/过滤坏项语义也不能作为严格唯一性依据。
- 已有producer使用AX→CG window ID映射。可按精确CGID用`kCGWindowListOptionIncludingWindow`核数值owner/layer/可见性（依赖接口由测试方T0466独立源码核对），不读取标题/应用名，不输出全局inventory。私有AX SPI失败必须unknown，不能几何匹配补齐。
- 既有target ax_closure会核AXFocusedWindow与绑定根的CFEqual；发现新身份不应取消该保护，也不隐式激活窗口。

## 新合同的最小范围

建议独立一次性入口和精确命名的身份发现Tool，名称在实施时一次确定并写入manifest；本文不提供猜测的可执行命令。它复用F026最早分流和私有状态策略，但不启动固定target daemon，不注册普通工具集合，不改变原两RPC。

显式参数仅支持`bundle_id=com.apple.TextEdit`与新UUID nonce；不接受任意bundle/PID候选、标题正则、坐标或公共session字段。生产普通模式默认行为不变。固定TextEdit是本轮实验边界，不宣称通用应用支持。

处理顺序：

1. 先验证私有绝对根/策略、参数和冲突环境；canonical standard/policy检查先于原生查询。缺AX只读拒绝，不弹提示、不请求录屏。
2. 只查询指定bundle的运行实例，恰好一个存活且可反向核对的PID；零个、多个、错误或读取不完整均拒绝，不能过滤坏项后挑一个。
3. 严格读取该PID的AXWindows，要求唯一实际AXWindow+AXStandardWindow、同PID和有效精确CGID。零/多窗口、重复、dialog/sheet、未知角色、属性失败均unknown。只查询身份/角色/必要的关联状态，不读取AXTitle/AXValue/文稿路径/正文。
4. 用精确CGID核所有者和普通可见窗口性质，禁止全局遍历后挑最大面积/z/最前窗口；隐藏/最小化或不能确定的状态拒绝。
5. 再取同bundle实例、窗口对象/ID及CG数值证据，要求前后稳定且仍唯一；保留对象连续性证据，但不称为永恒OS生命周期标识。实例退出/窗口重建/CGID复用/样本变化拒绝。
6. 成功仅输出固定版本、scope、nonce、采样时刻/序列及数字PID/CGID，明确`identity_only`；失败只输出闭合原因码，不能留下可当成功绑定的候选。无titles/values/screenshots/frame/globalrows/rawerror。

任何已发现的弹层或相关关系不明均拒绝；成功不声称全局无弹层、正文为空、焦点或可操作性已证明。后续仍需显式固定目标并重新执行F026生产topology RPC，不能把发现结果缓存为授权或自动进行输入。

## 权限与scope须明确实现

core `capture_scope.rs:155`只有Window/Desktop/Unscoped，不存在App枚举。本方案不新增公共capture scope枚举：发现没有截图/输入、也没有预先绑定窗口，使用Unscoped的capture分类，同时显式注册为R2/active private_observation、专用policy capability及固定bundle硬约束。

Unscoped不是无权限或R0；不能依靠未知tool的默认分支碰巧通行。须同步authorization的operation集合/映射、tool capability/已知工具目录、policy及私有参数schema；精确新工具名以外仍Unclassified/拒绝。configured managed/user deny保持上限；原两RPC专用policy不能自动允许发现能力。无需为了找到窗口解锁Desktop或伪造Window。

该应用范围是业务授权边界而非现成capture scope。是否需要新增保护资源scope key需实施时核core路径，但不能扩大其他private observation的默认授权或将显式bundle选择变成全应用授权。

## 必要验收

- 正例：唯一存活实例、唯一真实普通AX根、精确owner/CGID，A/B连续性成立；输出限固定数字与枚举。
- 负例：0/多实例、0/多窗、坏项/重复/缺subrole、dialog/sheet、隐藏/最小化、AX错误/超时/拒绝、SPI失败、CG缺失/owner错误、进程退出/窗口替换/ID复用、前后变化，全部无候选输出。
- 合同：其他bundle、extra/reserved字段、坏nonce、policy deny、unrestricted/worker继承、未知近似工具名拒绝；deny时生产查询调用次数为零。
- 隔离：不读旧config/history/PiP，不注册input/capture/browser，不启动服务/应用或弹系统权限；缺AX停点与身份不唯一停点分别记录。
- 交接：发现成功不授予输入权限，不改变固定target后续focus检查，身份已失效不能继续绑定。
- 先纯测试/独立审查/标准patch镜像与hash冻结，再测试方check/test/link。注入数据只证明逻辑，必须另有真实生产发现与固定target RPC证据；仍不代替T2/T3。
