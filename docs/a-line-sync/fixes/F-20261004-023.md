## 已定位的启动隔离缺口

| 边界 | 源码证据 | 结论 |
| --- | --- | --- |
| IPC与PID | `crates/cua-driver/src/main.rs:624`；`serve.rs:377` | --socket有效，但PID仍写HOME/Library/Caches/namespace，不能仅靠socket隔离。 |
| 配置 | `crates/pip-preview/src/lib.rs:23`；`crates/platform-macos/src/tools/mod.rs:581` | Local产品也读现有 `.cua-driver/config.json`，未提供私有config根；不得读取/复制私人配置来凑隔离。 |
| History | `crates/cua-driver/src/main.rs:557`；`history_runtime.rs:73,396,427` | 持久admission与CLI显式开启取OR；不传experimental-history不等于关闭，缺显式禁用。 |
| GUI/权限 | `crates/cua-driver/src/main.rs:590–705`；`crates/platform-macos/src/permissions/gate.rs:157–194,401` | startup可开启PiP、overlay、更新检查，默认gate可请求AX和录屏；本轮不得启动。 |
| 身份 | `crates/cua-driver/src/bundle.rs:10–35,92–113` | 用源码定义的Local名称才可靠进入local namespace；任意新ID或只加socket不够。 |

已证实的开关：`CUA_DRIVER_RS_TELEMETRY_ENABLED=0`关闭遥测（telemetry.rs:216），`CUA_DRIVER_RS_UPDATE_CHECK=false`关闭更新检查（version_check.rs:459），`--no-overlay`关闭overlay。telemetry专用目录变量不隔离其他配置。未发现可满足本方案的 --config、--pid-file、--no-history、--no-pip。

`--no-permissions-gate`只是不自动弹系统权限流程，不授予AX/TCC，也不等于取消工具审批；不得将其作为静默放宽授权的办法。需要无自动提示的只读启动模式时，必须明确记录该模式与人工授权停点。

## 最小修正方向（本轮未实施）

1. 建立一个明确、私有、绝对路径的状态根，覆盖driver配置、PiP配置、PID、history和日志；不修改或重新定义HOME/PATH，不读取旧配置作为fallback。路径无效应失败，不退回旧目录。
2. 显式关闭history/PiP，优先于旧持久偏好；只读模式不初始化capture/input/browser/profile或自动权限提示。保持正常生产默认行为不变。
3. 私有socket和最小工具policy：只允许下述两项生产RPC。保持standard、policy deny和unknown拒绝，不使用bypass/unrestricted/approved-manifest/任何existing-profile grant。工具白名单是权限上限，不替代用户目标授权。
4. 补路径隔离、旧admission/PiP开启仍不能继承、无网络/GUI初始化、policy拒绝其他工具的离线测试；独立Sol复审后交测试方私有编译，再冻结新hash。不能使用本轮已编译binary冒充新隔离修复。

## 修正完成后的实机流程与停止条件

1. 测试方先占用环境并核新产物哈希；确认既有Local产品无冲突。独立父目录下使用`CuaDriverLocal.app/Contents/MacOS/cua-driver-local`、bundleID `com.trycua.driver.local`。不覆盖旧`CuaDriver.app`/`com.trycua.driver`，不调用全局install/launchctl/autostart。
2. 新bundle、签名和权限是独立步骤，记录签名前后身份。不能宣称继承旧TCC、复制TCC数据库或执行reset。若启动需要新的系统权限，由测试方明确交给人工；缺AX时停止，不为掩盖AX失败申请录屏。
3. 新私有目录/socket/config/policy/session；环境白名单不继承内部worker触发变量。明确关闭telemetry/update/history/PiP/overlay，不改全局HOME/PATH，不启动或复用个人浏览器。存在未审查的初始化副作用就停止。
4. 仅由用户/测试方明确指定受控空白窗口的精确PID和window ID；没有合规数字身份来源就暂停，不通过私人标题、截图或猜测前台窗口补齐。
5. 先capabilities，再用新nonce调用target RPC；只记录schema、producer、source commit、目标ID、nonce、root role/subrole/status、Space可用性、耗时和错误类，不输出私人内容。
6. verified只证明本次精确窗口的有界观测；unknown/拒绝/版本不符/超时即停止，不激活、不输入、不截图、不扩大到Desktop、不重放。同步CG/AX调用不能据JS deadline宣称已强制取消；清理前先确认进程/调用终态。
7. 普通根成功后，根变为dialog/sheet应unknown，恢复后必须重新观测；缺Space字段应unknown。由测试方安排受控人工状态变化，不由修复方操作桌面。两RPC成功仍不代表完整T2通过。
8. 只停止本轮精确PID/socket，保留脱敏证据；不使用默认stop/revoke-all，不删除既有产品目录。

默认standard的private_observation为Routine（authorization.rs:426–440），可能无需额外逐次工具批准；“保持默认审批”不意味着每次都会出现审批卡。目标RPC仍是R2/private_observation及精确Window scope，不降级成任意R0。

## CoreMediaBridge与rpath警告

独立审查核对锁定`apple-cf 0.9.3`与`screencapturekit 6.0.1`的Package.swift，两个target都名CoreMediaBridge；只读nm检查两静态库，发现重复AudioBufferBridge Swift metadata/accessor。两build.rs均输出Swift rpath，对应duplicate rpath警告。证据指向既有依赖桥接，不是新增拓扑模块；但不能仅凭来源已知断言运行无害。

[上游已合并PR159](https://github.com/doom-fish/screencapturekit-rs/pull/159)明确说明同名Swift模块及类型导致符号冲突，并将私有模块改名以隔离命名空间；作者报告Rust1.97开始显露链接输出。本机1.99与此描述相容，但不是本轮运行影响的证明。

保持警告可见，不加忽略重复符号参数，不盲升依赖或cargo update。后续单独评估精确上游修正的可回移性/ABI与打包影响，独立锁定、构建和运行验收，不混入F022冻结包。链接exit0只说明成功生成binary。
