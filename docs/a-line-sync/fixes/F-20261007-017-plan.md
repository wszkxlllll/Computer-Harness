## 优先级：Run 取消支配未结算结果

不把所有取消机械合并成不可覆盖 firstcause。区分本地审查首次结束原因与外部 Run 取消的终止语义：本地 timeout/error/result 原因可锁定，迟到 assessor 结果不能覆盖；但任何结果结算前外部 signal 已 abort，必须抛出外部原 reason，不生成 approval。理由是当前实现已保证取消 Run 不返回审批，timeout先发生不能弱化此保护。

- 外部 Run cancel 先到：立刻拒绝原 reason（包括 null、0、对象），并请求取消 assessor；后续 timeout/result/error 不覆盖。
- timeout 先到：先锁本地 timeout，再 abort 内部 signal；若 abort 回调同步重入触发外部 Run cancel，最终仍抛外部原 reason，不返回 fallback。
- timeout已触发、fallback仍未结算时外部 cancel：抛原 Run reason。fallback 构造/返回前再检查外部 signal，所有 catch/error 分支亦同；错误摘要/assessment getter 或回调在构造中同步取消也不得漏检。race返回后即使没有下一次await，最终signal guard也不能省略。
- 正常/异常 assessor 结果和 Run cancel 同一事件窗口：结果返回前检查 signal；当时已取消则抛原 reason。
- 已经结算的 fallback 之后才取消 Run：不逆改历史 Promise。实际派发仍受既有 Runtime 取消屏障；此包不新增派发、不修改 Runtime，也不以历史 fallback 为取消后行动授权。

对上述优先级必须有独立反例，不能只检查 throw 的 Error.message；用严格相等核原 reason 身份。不能吞掉外部取消转为 risk_model_failed。

## 最小实现合同

semantic_review 开始时建立单调截止时间（performance.now 等，不以 Date.now 跳变作为 deadline），race 包含 assessor promise、timeout 和外部取消。超时/取消使本地 evaluate 有界 settle，即使 assessor 永不响应；仍向 assessor 传递 abort。同步 classify throw 也安全进入已有 fallback，外部取消优先。计数仅一次，清理 timer/listener，避免取消后继续持有 context。

调用 classify 前、同步 classify 调用返回后、每次 await 后及接受 assessment 前检查单调时间和外部取消。timer 被同步阻塞迟交付时，代码恢复后拒绝过期结果，不将 late aligned 变 allow。JS无法抢占同步 classifier，不能宣称硬30秒抢占；可保证恢复后不过期放行。

首次本地 timeout锁存在 abort transport 之前，避免重入把已超时结果改为成功；但按上节外部取消仍支配结算。迟到 resolve/reject 都有处理者、不发 unhandledRejection、不改变已结算决策、不追加模型调用或审批。退出所有成功/异常/取消/超时路径均清理自有 timer 和 abort listener；不能把远端/assessor已停止当作本地 settle 的推论。

不扩大风险识别策略；普通 assessor 错误仍原有审批 fallback。安全错误摘要沿既有 bounded 处理，不把 arbitrary reason 或原始 context 加到日志。是否保留 Date.now 的历史 latency 显示可由最小实现决定，但期限只能单调；不为此改公共 schema。

## 必须验收的反例

1. 忽略取消、延迟 aligned/local 返回：超时审批而非 allow；永不settle也及时本地 fallback。
2. timer尚未交付但单调时钟已过期：同步返回、await后返回均拒绝；截止前正常结果保持原语义。
3. pre-aborted signal：classify0，原 reason；调用中cancel：立即原 reason；never assessor取消也及时settle。
4. timeout先、abort重入Run cancel；timeout先、结算前Run cancel；Run先随后timeout；result/error与cancel竞争，均满足明确优先级。
5. late resolve不复活、late reject无unhandled；同步throw；timer/listener清理和重复abort不重结算；每次最多一次classify。
6. local allow/mandatory approval/deny、无assessor、预算耗尽保持原路径；本地规则不可被迟到模型覆盖。

作者定向 risk-guard tests 与包级类型检查；不同 Sol 独立构造上述竞争反例，再按影响执行既有 risk-guard runtime-regression，不重跑全仓来累计数字。冻结后由（10）按需要统一构建/运行切版；本包离线不声称真实 Guard 识别效果、API成功或总计划完成。
