## 必须改进的消费合同

现有CuaWindowInventory只有全局complete；Windows probe的read(signal)不接目标且source锁win32，合并允许不同采样行变化。新的Mac目标闭包必须单独表达scope、目标、producer/schema、采样时间与generation，不能伪装为全局清单完整或win32探针。

动作前保护、动作后diff、同ID sheet/menu/overlay检测要实际消费新合同。现有bounded overlay unknown且未观察到候选不是可信absence；新增RPC不能仅旁挂而不改变合法native执行路径。跨进程保存面板不能继承同PID+精确owner子窗授权。

Producer只读：CG全层数字快照A/B、仅目标AX关系，不收标题/正文/value/截图或无关应用AX。明确枚举/查询success、unsupported、error、计数、丢行/重复、归属边、可见性/z方向。unknown不转换false，取消/超时有界。双快照不能自称原子；无可靠生命周期证据时不造能排除所有ID重用的generation。

## 最小验收矩阵

| 场景 | 放行或拒绝标准 |
| --- | --- |
| 普通目标窗无变化、纯文本转换 | 精确目标闭包证据；动作一次；合法后状态不误报；逐动作前台守卫保留 |
| 独立sheet、同ID sheet/menu/overlay、关闭恢复 | 精确关系与根语义；Surface generation推进、旧引用失效；检测不只依赖CG新ID |
| 无关窗、同PID无owner、多个子窗 | 无关AX零查询、零自动切换；未知或多义必须manual/unknown，不猜owner |
| 跨进程保存面板 | 按明确选择/授权和精确身份处理，或准确报告限制；不自动继承父窗权限 |
| CG失败/丢行/重复/非法计数，AX拒绝/截断 | 负证据不洗白；动作前零派发，动作后保留completed并停止、零重放 |
| 目标消失、ID重用、旧generation | 旧证据失效；同PID/windowId不足以恢复授权 |
| A/B竞态、几何/z/Space变化 | 相关状态不稳定unknown；不能从两次相同数字清单证明中间无弹层 |
| RPC缺失、未知schema、超时/取消 | unsupported或类型化unknown；不静默关闭保护或运行时替换driver |
| Windows回归 | 原完整探针、精确owner、前台拒绝、无重放和人工交接不回归 |

## 必须实机证明

原生编译及新binary来源/指纹、实际Host/CUA版本/RPC协商/TCC只读能力；TextEdit focused/frontmost冲突拒绝；纯文本转换的实际前后证据；保存面板真实PID/CG/AX表达、菜单/关闭/恢复父窗、旧引用失效；多显示器/Space可用环境及残余限制。离线mock不能替代这些。

最终T2基线/独立新空白复验/完整变体均须Harness真实六行输入、UTF8保存、GUI重开、全部字节及末尾一个换行比对，40requests/60steps保持。不得预写、修正文件或复用已输入正文。原I0408/I0409未关闭，T0442未采原始清单，因此不能宣称missing complete就是当次唯一trigger。
