## 本轮已修复、有回归证据

- 设备间 Run、事件、命令回执和截图归属检查遗漏。
- 设备撤销后 SSE 继续发送，以及异步窗口枚举完成前撤销的竞争条件。
- 超前事件游标的 resync 丢弃问题。
- 去重缓存淘汰可能让旧命令重复执行：改为容量满时拒绝新键，不承诺跨重启去重。
- 资产路径穿越及普通符号链接/junction 越界防护。
- Node 24 WebSocket 成功回调 `null` 被误当错误。
- 审批缺少具体动作预览、窄屏长回复显示，以及 Web 测试未被根测试入口收集。
- 异常桌面锁恢复的 acquire/recover 并发竞争与审计事务问题。
- CUA 截图通用拒绝吞掉底层原因：已加入安全分类；**只修可诊断性，没有修复捕获本身**。

## 下一阶段顺序

1. Guard 离线投影检查和新诊断脚本安全审查已完成；保留冻结检查点，恢复实机前置环境后补跨窗口验证。
2. 对底层输入与捕获继续做最小隔离实验，再决定通用修复方案。任何新方案需独立回归及真实复测。
3. 通过真实窗口交接与原生任务门槛后，才扩大日常应用承诺。
4. 与上述工作独立准备服务器 staging；真手机验收通过后才宣称“扫码即用已验证”。

执行平台或测试工具报错单独记录，不能自动算成产品缺陷；同样也不能因为是测试工具失败就宣称产品已经通过。
