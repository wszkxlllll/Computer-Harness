## 修改意见（待实施）

### P0：预算耗尽前保留收尾回合

当前运行时在达到 `maxModelRequests` 后直接写入 `runtime.error` 并结束运行，没有给模型留下整理结果的机会。建议：

1. 当剩余模型请求数为 1 时，禁止新增复杂 GUI 操作，只允许 `finish` 或受限的结果整理回合。
2. 如果最后一回合仍未正常返回，运行时自动生成结构化收尾：已确认字段、未找到字段、已完成步骤、未完成步骤。
3. 收尾内容应明确标记不确定值为“未找到”，不得为了完成任务而猜测。
4. `maxSteps` 仍作为 GUI 动作上限，不能用提高 `maxModelRequests` 替代收尾机制。

涉及位置：`packages/runtime/src/run-controller.ts` 的预算检查与模型回合循环（约 596 行）。

### P0：DOM 候选过期后自动重新定位

本次 10 次 GUI 失败均为 `DOM_CLICK_CANDIDATE_STALE`。建议在低层 CUA 执行器增加一次受控恢复：

1. 遇到 `DOM_CLICK_CANDIDATE_STALE` 时，先重新获取观察结果。
2. 使用新观察中的相同 role/name 候选重新绑定 DOM 指纹。
3. DOM 候选仍不可用时，按安全顺序尝试 UIA 候选；只有确认点位稳定时才使用坐标候选。
4. 自动恢复最多执行一次，避免在页面变化时重复触发点击。
5. 恢复失败后返回明确的“需要重新观察”错误，让模型换路径，而不是重复原点击。

涉及位置：`packages/computer-cua/src/cua-driver-computer.ts` 与 `packages/computer-cua/src/managed-browser-host.ts` 的 DOM click 分支。

### P1：连续滚动增加收敛阈值

长任务中出现了 18 次滚动和重复寻找参数的行为。建议：

1. 对连续滚动次数、连续无新字段次数分别计数。
2. 连续 3 次滚动没有新增有效信息时，生成非阻断提示，要求切换到比较表、规格表或站内搜索结果。
3. 页面已经进入页尾仍未找到字段时，直接将该字段记录为“未找到”。
4. 已收集到最低完成条件后，优先整理结果，不继续无界面浏览。

### P1：修正工具调用编排

本次有 6 次调用因为把 `memory_get` 与 GUI 操作放在同一模型回合而被拒绝。建议：

1. `memory_get`、`memory_search` 等读取操作单独占用一个模型回合。
2. 只有 Planning/Memory/ExecutionSegment 写操作可以作为 GUI 操作前缀。
3. 在 Provider 适配层或运行时预检阶段提前拆分非法组合，避免先产生一整批必然被拒绝的调用。
4. 对 `scroll.direction` 做更早的枚举校验，直接拒绝或规范化非法方向。

涉及位置：`packages/runtime/src/run-controller.ts` 的 `validateCompositeCallOrder` 和工具参数校验。

### P2：降低 API 延迟的放大效应

本次 Provider 平均响应约 15 秒，最长约 76.6 秒，但没有 HTTP/网络错误。建议把它作为性能优化项处理：

1. 减少重复观察和无效滚动，优先降低请求次数。
2. 控制历史事件和图片上下文大小，避免每次请求重复携带大段页面信息。
3. 保持单回合输出上限，避免一个推理回合占用过长时间。
4. 记录每次请求的首字节、完整响应和工具执行耗时，区分 API 延迟与本地执行延迟。
5. 不建议仅通过提高 API 超时阈值解决问题；本次最长请求尚未达到 90 秒超时阈值。

### 建议实施顺序

1. 先实现预算收尾回合，防止“已完成大部分工作但直接失败”。
2. 再实现 DOM stale 的一次自动重新定位，减少无效模型回合。
3. 增加滚动收敛阈值和“未找到”降级策略。
4. 修正 Memory 与 GUI 混合调用及滚动参数校验。
5. 最后根据新的运行数据优化 API 延迟和上下文大小。

### 验收标准

- 长任务在预算达到上限时有明确总结，不再只返回 `budget_exhausted`。
- 同一运行中 DOM stale 自动恢复成功率可统计，且不会重复触发有副作用的点击。
- 连续无进展滚动能够在阈值后切换路径或标记“未找到”。
- `memory_get` 与 GUI 操作混合回合不再产生工具顺序拒绝。
- URL 导航仍保持只读放行，不能因此放宽购买、提交、删除、发送等高风险操作。
