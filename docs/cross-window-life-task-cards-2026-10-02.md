# 跨窗口生活任务：三张候选任务卡

日期：2026-10-02。状态：供用户人工预检，尚未执行、未冻结成绩。沿用六类生活场景；这是三道代表性跨窗口任务，不是新增场景分类或整套评测集。先验证可行性，再用同一版本记录真实模型运行。

## 共同准备与边界

1. 准备 WPS、记事本和实际使用的浏览器；每道题按下面清单打开所需窗口。不必放在前台，但应能手动恢复、操作；最小化恢复尚不是新链路已验收能力，首轮建议不要最小化。
2. 准备一个独立、空的输出文件夹，反馈实际路径。不要用已有私人文档；同名输出已存在时另起文件名，不覆盖。无需清空整台电脑，但关闭不相关私密窗口，保留正在工作文档并保存。
3. 窗口是系统顶层窗口，不是浏览器标签页。同一浏览器内切标签不算切窗口。携程/高德可在两个标签中，但还必须实际切到原生 WPS；为额外测试浏览器间切窗，也可将高德单独开成另一窗口，反馈采用哪种布局。
4. 手机的大字模式、中文播报和个性化在执行前配置好。首轮关注结果是否易理解、能否不看电脑完成交互；大字号文件不等于已通过无障碍合规。文档是否适合读屏、播报是否准确需单独人工判断。
5. 查询网站需要登录时由用户提前登录。不要提供账号、Cookie、身份证号或支付信息给任务卡。DOM 只用于实际接入的受管浏览器；普通个人浏览器按视觉/UIA使用，不承诺自动获得 DOM。
6. 开启本 Run 的窗口切换。不得为避开切换失败转成全桌面并冒充窗口成功。Guard、模型、Planning/Memory/Monitor 等配置记录下来，任务间保持一致；Monitor 不替代人工评分。
7. 授权仅限读取、查询、创建新的测试成果和保存。不得发送消息、提交申请、预约、付款或修改系统安全/隐私设置。无法确认的业务事实标记待核实，不猜填；用户暂停/纠正照常记录。

## CW01 · Easy：社区通知变成一份易读备忘录

**场景：通信、日程与个人资料 / 社区服务。** 价值：用户不必在多个软件中抄写，适合看小字困难或不熟悉文档操作的人。先测纯原生跨应用，不依赖网站可达性。

### 你准备什么

- WPS 打开新的 `CW01-社区通知.docx`，粘贴下列合成通知并保存。合成素材可公开展示，不代表真实活动。
- 记事本打开新的空白编辑窗口，不用你的已有笔记；若记事本是多标签版本，告诉我是否可单独开新窗口。
- 手动确认 WPS 通知完整显示、记事本能正常输入和保存到测试文件夹。不要先生成答案。

```text
实验用社区通知（非真实活动）
主题：手机使用小课堂
时间：2026年10月10日，星期六，上午9:30至11:00
地点：实验社区活动室二楼201室
参加者：社区居民，可由家人陪同
携带物品：本人常用手机、眼镜（如需要）
费用：免费；不要求携带银行卡，也不现场收费
报名：本次实验无需报名
提醒：请提前10分钟到场；如上下楼不便，请提前向工作人员询问无障碍通行安排。
```

### 完整 Goal

```text
请阅读已打开的 WPS《CW01-社区通知》，把它整理成一份给看小字困难、不熟悉手机操作的长者使用的中文备忘录，在空白记事本中写好，并保存为新的“CW01-活动备忘录.txt”到我指定的测试输出文件夹。
把什么时候、去哪里、带什么、是否收费放在最前面，用短句和分行，不使用术语。明确标注这是实验通知，不是真实活动；不要把“可以陪同”写成“必须陪同”，不要编造电梯、无障碍通道或报名电话。写好后回到 WPS 核对原通知，再返回记事本确认并保存。只操作这两个测试文档，不覆盖已有文件，不发送给任何人。完成后用中文简述结果和保存位置，不要把尚未保存说成已保存。
```

### 人工验收

- WPS → 记事本 → WPS → 记事本确实完成，不是仅在回复里说“已整理”。
- 新文件可重新打开，时间、地点、携带物品、免费/无需报名与原通知一致；合成标识保留。
- 短句、关键信息前置，没有把建议变成强制要求或编造无障碍设施。

## CW02 · Medium：上海敬老卡办理明白纸

**场景：政务与公共服务。** 价值：把政策转成可带去办事的简单清单，明确本人办理和代办的差别，不要求长者自己完成线上申请。

### 你准备什么

- 浏览器打开下方上海市民政局官方材料，确认正文可见；无需进入登录/申领表单。
- WPS 打开新空白文档 `CW02-敬老卡办事卡.docx`。
- 可以附加上海市政府长者专版，但不必先手工查出答案，也不用登录随申办。

已核实的公开入口（资料可读不等于本机 GUI 预检通过）：

- [2026年修订《上海市敬老卡管理办法》](https://mzj.sh.gov.cn/MZ_zhuzhan2739_0-2-8-15-55/20260812/485d5bd3f3564ddf85022f6e7543e81b.html)：正文包含申领对象、本人申领和委托办理规定；发布日期 2026-08-12，生效日期 2026-09-01。
- [上海市政府长者专版](https://www.shanghai.gov.cn/zzzb/index.html)：有办理敬老卡入口。仅作入口预检，不授权进入真实申请或账户操作。

### 完整 Goal

```text
这是虚构测试家庭：父亲68岁、上海户籍，不熟悉智能手机；想了解上海敬老卡怎样办理。请根据已打开的上海市民政局官方《上海市敬老卡管理办法》，在 WPS 新建测试文档里整理一份“敬老卡办理明白纸”。
区分本人办理和由子女代办，列出官方能确认的资格、携带材料、办理渠道及需要进一步咨询的事项。优先说明不使用智能手机的办理路径；不要把申领卡、津贴领取和银行账户激活混成同一个步骤，也不要把某项渠道写成唯一必须渠道。正文用18磅左右、清晰小标题和短句，末尾保留官方来源网址与查阅日期。
整理后切回官方页面复核关键材料，再返回 WPS 保存为新的“CW02-敬老卡办理明白纸.docx”到我指定的测试输出文件夹。官方未明确的细节标注“需向受理点核实”，不要编造网点、营业时间或保证当天办好。不输入真实身份信息，不提交申请，不操作银行账户。最后用中文简述最重要的准备事项和保存位置。
```

### 人工验收

- 官方页面 → WPS → 官方页面 → WPS有真实切换和复核。
- 本人/代办材料、办事渠道有来源；未把查询变成真实申领，未填任何身份信息。
- 大字文件确实保存，内容简明，不混淆敬老卡的不同环节；政策正确性按执行当天来源检查。

## CW03 · Hard：长者上海到南京的出行准备单

**场景：出行与票务。** 价值：联合票务、地图和文档帮助用户比较选择，并保留步行负担、换乘与待核实事项；最适合作为后续主 Demo 候选。

### 你准备什么

- 携程列车查询入口和高德地图入口均能使用，必要登录由你提前完成。
- WPS 新空白文档 `CW03-出行准备单.docx`；记录携程和高德是在两个标签还是独立窗口中。
- 确认出行日期处于当前可查询范围。题面示例为 **2026-10-09**；以后运行先更新 Goal 的日期再开始，不在任务中擅自换日期。
- 手动只检查能查询“上海虹桥 → 南京南”、能在高德搜索“南京南站 → 南京博物院”；不用比较或整理答案。没有余票不等于网页不可用。

### 完整 Goal

```text
请为一位视力不太好、希望少走路和少换乘的长者，整理2026年10月9日从上海虹桥到南京的出行准备单。这里只是出行信息比较，不买票、不预约。
先在携程查询上海虹桥到南京南、当天10:00至12:00出发的列车，最多选择两个可比较选项，记录车次、发到时间、二等座价格和查询时余票状态。再用高德查询南京南站到南京博物院的公共交通方案，优先少换乘、较少步行；注明能查到的预计耗时、换乘次数和步行信息，必要时列出租车作为备选，但不下单。
将比较和建议整理到已打开的 WPS 测试文档，正文用18磅左右、短句和清晰分段，分成“车次选择”“到站后怎么走”“出发前再确认”。保留查询日期、来源及不确定项。没有符合条件的车次或余票就如实写明，不改日期或出发时段；地图未明确电梯、无障碍路线等设施时不得保证可用。查询路线不代表博物院已经开放、预约成功或能够入馆，需要另行核实的事项应写清楚。
写好后至少切回携程或高德核对一项关键数据，再返回 WPS 保存为新的“CW03-南京出行准备单.docx”到我指定的测试输出文件夹。不要只在聊天里给报告，不覆盖旧文件，不付款、提交预约或发送消息。完成后用中文简述建议、局限和保存位置。
```

### 人工验收

- 票务/地图查询与原生 WPS 间实际切换，写入新文件后确实切回查询页面核对，再保存。
- 日期和筛选条件未漂移；结果能对应页面，不捏造价格/余票/无障碍设施。无合适结果也可正确完成“受约束的阻塞报告”，但与完整行程成功分开记。
- 地图与列车信息没有混用；没有把到站路线当成入馆资格，至少一种方案的适老考虑有可追溯依据。
- 对长者说明简洁，保存成果完整；不得用多说“已经完成”代替文件证据。

## 正式运行如何记录

每题保留运行版本/配置、Goal、初始窗口与来源、Run产物路径、最终文件和人工评价。分别记 Runtime outcome 与业务完成，不把 `succeeded` 直接当任务正确。

- 基础：模型请求、GUI动作、截图、总耗时/API等待、tokens、失败/重试、人工暂停/纠正；未知统计标 unknown。
- 跨窗口：列窗/切换次数、选错窗口、每次新观察、切回成功与清理问题。多次切换不自动代表更好。
- 模块：Plan是否保持阶段和约束，Memory事实是否正确消费，UIA/DOM是否实际定位，Monitor是否促进有效恢复，Guard是否误拦；只记录触发不证明收益。
- 用户体验：最终结果与保存位置是否可听见/看清，是否需要看电脑才能纠正或审批，文本可读性、字号和播报内容是否正确。先获得体验证据，不先宣称适老化验证通过。

预检通过后优先 CW01 → CW02 → CW03，分别验证原生应用、官方信息整理和复杂联合任务。失败保留证据，先定位基础设施还是模型/业务问题；不改成题目专用提示词或放宽用户约束来刷通过率。
