# 手机端适老化与无障碍体验审查、实施记录

日期：2026-10-08。范围：当前手机 Web 控制面及其现有语音、任务状态、审批与恢复链路。目标是降低使用门槛，不把产品改写为仅面向老年人的专用助手，也不将源码检查当作真实用户研究。

### 2026-10-09：从生活任务倒推体验

并不是所有老人都需要代操作，也不是每件小事都值得启动电脑。手机已经能轻松完成的事项，不应人为绕到电脑。产品优先承接电脑仍有优势或现实限制的部分：阅读和整理长通知、比较多处信息、处理需要下载／打印／保存的文件、准备办事材料和交给家人的清单。具体事项规则仍以实际来源为准，这些是体验设计场景，不是已经验证的办理能力。

| 用户要的结果 | 产品应减少的负担 |
| --- | --- |
| “把这份长通知说清楚，我要带什么、什么时候去” | 不先要求理解文件类型、窗口或技术设置；先给结论，允许重听和展开原文 |
| “把出行要用的信息排成大字清单，方便我带走” | 不只汇报点击过程；结束时说明准备好了什么、文件在哪、下一步怎么用 |
| “帮我把表填好，先给我看，不要提交” | 尊重停在确认前的要求；把待确认的内容与后果说清楚，不用模糊的“允许操作”代替解释 |
| “我刚才没听清／我想改一下／先停一停” | 允许重听、纠正和停止；不要求重说整个任务，不混淆停止朗读与停止任务 |

首屏只让用户表达需求；进行中突出“现在怎样、是否需要我处理”；结束时突出能用的结果。主要界面使用普通中文，不出现Host、Run、回执、DOM等工程术语，不反复显示同一状态，不让解释占满屏幕。设置和诊断逐步展开，但付款／对外发送等关键授权、录音状态和任务停止入口不能藏起来。品牌、真实网址和用户文件名保留实际内容，不能为了全中文而篡改结果。

这仍是待用户验证的设计假设，不宣称替代真实老年人、低视力和盲人访谈；三类使用者的视力、听力、运动能力和数字经验各不相同。

本轮不是重新设计产品，也不把上面的例子做成任务专用提示词、快捷模板或应用特例。保留现有蓝色浅色界面、导航和执行架构，只收敛状态、审批、朗读、结果与失败重试的既有交互。判断标准是用户能否看懂和操作，不是页面上是否写了更多“关怀”说明。真实任务内容、文件名、网址和模型结果保持原样；普通中文用于产品自己的按钮和说明。

## 1. 当前结论与证据

6.1 Sol 已完成只读源码审查，未确认新的 P0／P1 回归；本轮由 Luna max 实施局部改进，审查发现的两项 P2 已修复并复核。保留已认可的 APP 式布局、现有颜色和导航，不重新套用页面模板。实际完成与未验收项见第5节，不把设计意图当成验收结果。

语音当前实际是点击开始、点击结束，并非长按录音。已有取消、60 秒上限、识别后检查编辑再发送、文字输入兜底和权限错误处理。需要修的是“按下说话”造成的误解，不应据此重复建设语音链路。

已有大字、简洁布局、高对比、减少动画、语速和自动播报偏好；已有请求新鲜度检查、截图查看器焦点管理和真实控制回执。不能为了方便移除这些能力，也不能把“大字版存在”称为已完成视障用户验收。

## 2. 本轮优先修改

| 用户遇到的问题 | 当前源码证据 | 实施方向与约束 |
| --- | --- | --- |
| 等了很久，不知道电脑在忙、断开还是等自己 | RunWorkspace 当前状态不够显眼，EventTimeline 在简洁模式折叠 | 常驻真实状态与最近实际进展，区分任务状态和手机连接状态。不能按耗时计算完成百分比、伪造预计完成时间或推断成功 |
| 需要决定是否批准，却先看到大量操作细节 | PendingRequestPanel 把电脑动作的 reason 折叠在更多信息 | 决定前直接显示原因、动作和后果。说明与真实证据分开；不放宽旧引用、截图与未知副作用规则 |
| 没听清结果，找不到再听一次 | ResultPanel 没有主动重听控制 | 复用现有输出适配器提供主动朗读和停止；尊重语速，避免与通知或录音互相竞争，不自动打开麦克风或改变自动播报偏好 |
| 初次加载失败只能退回列表，不知道任务是否还在跑 | RunWorkspace 无快照错误分支缺少直接重试 | 加入直接重试，明确连接断开不等于电脑停止。重试只刷新同一 Run，不重新发起任务或重放动作 |
| 不知道录音要不要一直按住、说完会不会直接执行 | VoiceInputControl 的“按下说话”文案 | 明确点击开始／结束，录音前说明时限和检查后发送；保留取消、识别失败清理和文字兜底 |
| 配对提示说会自动进入，但实际还需点按钮 | PairingScreen 承诺与行为不一致 | 修改为符合真实流程的说明，不增加自动授权 |
| 放大字体后操作困难，浏览器默认字号被覆盖 | styles.css 固定根字号，预设大字不等于 200% 放大 | 相对字号、重排和足够大的点击区域；保留键盘焦点和减少动画。真实浏览器放大与读屏测试单独记录 |

变更以现有数据为依据，不增加模型调用、虚假状态字段或上下文维护负担。UI 的字体／布局偏好不作为模型推断残障或年龄的依据；现有用户明确填写的回答偏好仍沿既有快照进入 Context。

## 3. 不能靠文案宣称解决的部分

1. **独立非视觉审批**：当前部分审批和窗口候选需要查看截图。图片替代文本不能证明正确窗口、当前焦点和操作后果。应解释限制并提供拒绝／求助路径，不替用户确认图片。可信的非视觉证据需要另外设计与验证。
2. **完全免触控对话**：持续监听、后台唤醒、自动执行语音命令不属于当前录音合同。浏览器权限、前台生命周期、误触发和隐私均需处理。后续可以研究用户明确开启的有限对话模式、说完自动结束及安全停止命令，但不能用常开麦克风冒充本轮完成。
3. **真实用户成效**：代码和 DOM 测试不能证明老人、盲人、低视力或运动障碍用户都能独立完成任务。后续分别招募用户测试，不将群体混成一个“大字模式”画像。

## 4. 验证与完成标准

- 录音：点击语义、开始／取消／结束、失败清理、识别后仍需检查发送，复用现有测试适配器验证，不偷偷上传新的音频样本。
- 状态：运行、等待审批／输入、暂停、停止中、终态、断连和恢复均由真实快照／事件驱动；计时刷新不能造成连续读屏播报。
- 审批：原因在决定按钮之前可见且可读；证据变化仍阻止旧审批，没有新增跳过安全校验的便利入口。
- 朗读：用户主动朗读不依赖自动播报开关；支持停止、失败反馈和不支持环境降级；与既有语音输出、录音和 Run 生命周期协调。
- 布局：现有单测和类型检查；浏览器实际检查窄屏、字体放大与操作区遮挡。不能把 DOM 测试写成 VoiceOver／TalkBack 或真手机音频测试。
- 回归：现有任务控制、审批、配对、窗口候选、个性化与语音测试保持；不改 Runtime、Computer 和 Provider 协议来迁就展示。

### 后续用户验证

请分别观察：能否知道“现在发生什么／是否要我做事”；能否不依赖颜色理解状态；能否找到并使用停止和纠正；是否误以为断网会停止电脑；是否能重听结果和找到输出位置；放大或读屏后能否完成输入、审批和恢复。记录实际求助、误触、重复操作和任务结果，不只记录满意度。

## 5. 实施与验收记录

### 2026-10-09：字段生产／消费补查修正

用户询问预览字段是否都有真实对应后，协调者发现此前验收漏项：Web `RunSummary.updatedAt`及继承它的`RunSnapshot`曾仅由测试和模拟预览数据提供；真实`RemoteRunApi.snapshot()`没有生产它。该字段有前端消费者但没有真实生产者，同样不符合字段闭环原则；原模拟输入通过不能作为真实链路验收。

其余主要映射已核对：标题来自Host的goal；当前状态来自Runtime状态投影；上次进展来自`run.notice`的progress文字或`run.progress`事件标签；审批来自pendingRequest；暂停／恢复／停止／纠正由capabilities和既有命令回执链路承接；结果来自reply／outcome。客户端connection表示事件流连接状态，不单独证明电脑当前画面或任务效果。进展可能是运行阶段提示，并不保证每次都有具体完成事项。

用户确认移除后，Luna max已删除该字段、页面时间、朗读时间、格式化函数、专用CSS、测试中的假时间及QA模拟字段，不补新协议或用手机当前时间替代。Task／Memory等其他业务字段未动。Sol定向复核通过；协调者完整Web回归25文件／195项通过，实施者RunWorkspace 18项、Web noEmit和QA脚本语法检查通过。`rg -uuu`确认Web源码及当前合成夹具无残留引用。

当时的本机4335只读预览曾单独重启，内存模拟数据同步去掉该字段；截至2026-10-09后续核验，该临时监听已停止，不能再通过刷新查看。服务器、真实Host、CUA和登录配置未改。这是孤立字段清理，不是全项目所有协议字段的穷尽审计。

2026-10-09：功能源码已冻结，6.1 Sol完成一轮审查及两项整改的短复核；Luna max完成实施。保持既有页面与执行合同，不增加模型调用或业务任务模板。
