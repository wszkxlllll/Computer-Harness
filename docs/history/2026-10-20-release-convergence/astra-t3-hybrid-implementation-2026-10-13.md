# T3 Hybrid Recovery Implementation

This change adds a Host-owned `native-web-document` run target for the T3 Browser-to-TextEdit workflow. The Host exposes only an opaque profile identifier and display label. Its private profile fixes the initial TextEdit window, same-process recovery blank, absent output path, canonical TextEdit executable URL, and the Browser companion URL (`https://trains.ctrip.com/`). The browser profile is forced ephemeral, including when the Host's ordinary managed-browser settings are persistent.

The Web and Relay boundaries accept only `{ mode: "native-web-document", profileId }`. Callers cannot provide a PID, window, URL, document path, profile directory, or recovery policy. Host start requests preserve the goal text exactly, consume the profile once, and remain idempotent for retries carrying the same command ID. A second command cannot consume the profile again.

The CUA adapter receives the Host's exact primary/recovery pair and the opened managed Browser identity as separate capabilities. The Browser is admitted for ordinary switching and browser-only DOM grounding without being merged into the native recovery allowlist. The recovery blank is withheld from ordinary switch and handoff choices and is admitted only after the completed bound-window-missing boundary. `ManagedBrowserComputer` forwards the Host's single-file reopen grant to the adapter.

Validation is offline and synthetic. The ApplicationSession fixture runs the production CUA adapter and production managed-browser assembly against fake CUA and Browser drivers through one complete Run: Browser switch and DOM observation, return to TextEdit, type and save, completed close, exact missing-window recovery handoff, one-shot reopen, `sessionAfter`, and a fresh observation on the reopened window. The fake only creates the output file at the simulated save boundary and records one launch. Host HTTP, Relay forwarding, Web submission, and target-parser tests cover the normal entrance and reject caller-controlled fields. No live Provider request, browser business result, or desktop application interaction is asserted by these fixtures.

The Host profile is configured only on Darwin through `HARNESS_NATIVE_WEB_DOCUMENT_*` settings. The private Host configuration file must remain outside the repository. Windows and Linux native profiles are not supported by this implementation.
