## 3. 优先级与放行边界

这里 P0 表示“进入相应真实产品场景前必须修复”，不是要求先停止所有实验。

| 优先级 | 问题 | 阻塞什么 |
|---|---|---|
| P0 | 审批后仅比 Observation ID；没有外部焦点/目标新鲜度验证 | 真实高风险批准后的自动动作 |
| P0 | Guard 描述性关键词豁免可跳过风险信号；低风险仍依赖模型自述 | 宣称可靠保护财产/隐私 |
| P0 | TUI 与 CUA 共用前台键盘焦点；交互可能改变动作目标 | 在个人桌面边操作边对话 |
| P1 | 功能开关与依赖实例存在两套输入，缺少组装不变量 | 多入口、TUI 和 SDK 长期维护 |
| P1 | 缺少 CI；本地源码测试与 workspace `dist` 可能混合 | 大规模拆分后可信合并 |
| P1 | CUA 无版本/合同发现、引用绑定有限、清理不具备严格超时 | 稳定安装、升级与故障恢复 |
| P1 | 全历史轮询、无模型流式 UI、纠正等待模型返回 | 长任务实时体验 |
| P1 | 原始轨迹/Provider 日志有内容，UI 隐藏不等于数据脱敏 | 分享日志、语音接入和隐私承诺 |
| P2 | 窗口/元素定向、受控后台输入、语音、图片传输优化 | 后续产品质量；可按独立门槛推进 |

## 4. 建议实际执行顺序

1. **建立 CI 和组装合同**：先固定干净构建、离线回归和功能开关一致性；提取共享应用组装，开始行为保持拆分。
2. **并行做两件事**：一条线用 Fake Computer 完善事件订阅和持续 TUI；另一条线隔离比较 CUA 0.22.2/0.28.2。升级与窗口功能分开提交和验收。
3. **修复交互与 Guard 边界**：修规则豁免；审批绑定动作；用户接管后重新观察和定位。先在合成场景证明确实不误执行。
4. **低风险本机体验**：固定文本编辑/窗口切换/暂停纠正场景；先做主屏幕保守模式，再做窗口定向模式。允许结果不好后继续改，不要求先通过整批 OSWorld。
5. **窗口/元素能力和语音接入**：各自独立开关、独立基线。语音先进入既有命令面和最终回复播放，不为每个动作追加模型播报。
6. **发布可复现候选**：保留版本/配置/模式/验证证据，手动发布。正式 P/C/B/M 消融沿用自己的冻结版本，增强桌面工具不能偷偷进入原有模型对照。

不以所有长期功能全部完成作为开始体验的前提。长期 Memory、Advisory、Sandbox、Execution Subagent 仍保留，但本轮不新增其实现。

## 5. 交给实施 Agent 的方式

先读本文件和目标分项，再读代码及分项所链接的旧设计。以本轮证据修正旧设计中的过时陈述，不能把建议类型、拟建工作流或上游文档能力当成当前已实现能力。每一改动需报告生产者、消费者、失效/清理、回退开关和本次验证范围。
