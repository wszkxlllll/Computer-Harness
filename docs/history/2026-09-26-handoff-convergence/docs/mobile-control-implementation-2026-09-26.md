## 分工与集成顺序

1. Host：Fastify + 真实 ApplicationSession，定义远程 DTO、请求绑定审批/选窗、命令去重、事件和鉴权资产。
2. Web：React/Vite，手机任务页与电脑配对入口，实际连接 Host，支持结果、纠正、控制和断线恢复。
3. Relay：设备主动出站连接、隔离路由与断线处理；先本地验证，公网部署须确认托管条件。不得把无 VPN 的公网扫码能力报告为 localhost 联调已经实现。
4. 实机：先准备并独占桌面执行此前窗口验收，再验收新入口。至少两个出行类别及浏览器、记事本、WPS；不得跳过失败，保留原始失败并独立复测，未知副作用不得盲重试。
5. 集成后由 GPT-6 Sol Medium 集中审查，GPT-6 Luna Max 修复；主 Agent 负责合同与范围协调。实施使用 GPT-6 Luna Max。

共享 Runtime 不依赖 HTTP/Web；单一 Host 拥有执行器。私密截图只本地保留；前端不能指定任意本机文件、Provider 密钥或任意 CUA 方法。两端均需展示已接收与实际生效的区别。

## 放行门槛

- 离线：类型检查、现有回归、配对过期/撤销、CSRF、跨 Run/设备隔离、旧审批拒绝、重复命令、慢订阅与重连。
- 联调：真实应用装配，不以 mock 成功代替 Provider/Computer 接通；窗口选择与审批必须可在 Web 完成。
- 实机：用户于本轮授权释放电脑进行测试；不购买、下单、付款，不操作无关账号。真实 API 测试开始时说明用途。
- 手机：须真实设备扫码；当前尚未获得手机端验证证据。公网托管未就绪时明确阻塞项，不冒充扫码即用。
- 交付：实际运行命令、依赖/部署配置、证据位置、通过项/未验证项/失败项及回退方法。

## 集成检查矩阵

| 场景 | 必须观察到的结果 |
| --- | --- |
| 连接手机 | 桌面入口生成配对链接/二维码；未确认的手机不能读取 Run 或截图；确认后进入任务页。 |
| 撤销与过期 | 过期/已消费二维码不可再次建立配对；撤销设备后现有 HTTP 与事件连接失效。 |
| 桌面管理隔离 | 中继不能访问 local 管理路由；伪造 Host/Origin/代理头不能获得本机权限。 |
| Run 与命令 | 重复 start commandId 不产生第二个 Run；同一 ID 不同载荷拒绝；旧 Run 命令不能作用于新 Run。 |
| 审批/选窗 | 同意精确绑定当时待处理请求；过期请求拒绝；新窗口选择取得新观察后继续，不重放未知动作。 |
| 用户补充 | 运行中纠正、暂停、恢复、停止有明确回执和实际状态；控制服务不等待模型完成才接收 Abort。 |
| 结果与资产 | Run 结束后仍能阅读完整回复和授权截图；不能通过路径穿越、符号链接或其他 Run ID 读任意文件。 |
| 重连 | 页面刷新/网络断开后获取快照和事件水位；不重复发送 GUI 动作；中继断开不自动确认审批。 |
| 单执行器 | 第二个 Host 或 CLI 不得因使用不同管道地址而抢同一物理桌面；无法覆盖的旧入口需明确阻止或报告。 |
| 手机布局 | 窄屏、大字时 Goal、完整回复和审批可读可操作；不会因事件不断重绘而丢失用户输入。 |
| 中继资源 | 有界消息/队列/超时；已断开的手机和电脑释放订阅；部署明确 TLS、域名、配对存储、日志与升级步骤。 |

最终技术报告按“用户现在能做什么 → 架构与数据流 → 测试及失败复测 → 服务器部署 → 未解决限制”编写；每项注明实测、代码审查或仅设计，不复制私密截图。
