## 原生缺陷与最小合同

Astra 只读固定 CUA 0.22.2 commit d114f35fec05ecd37bf529e5587be86852205b64 的 platform-windows tools impl_.rs：CurrentValue 读取失败转空串后 SetValue 可能覆盖旧文；同一 worker 的 Result 又经 ok/unwrap_or(None) 变成不支持 ValuePattern，导致读取失败、写入失败或 worker 错误仍可能进入 WM_CHAR fallback。仅将前一个 unwrap 改为问号仍会被后一层吞掉，必须同包处理。

（6）已准备另一隔离 Windows source `/private/tmp/Windows-Append-20261007.QzOhL4/source`，clean detached 固定上述 commit，Cargo.lock SHA256 为 cb7cdf7d03eee68f2dd48b6dc75a6005e74ca96a5604a7a88a2994ddd5125a2f，无 Mac patch。唯一 Sol medium 作者在 F014 后修改 impl_.rs、新增纯 std value_append 模块及 lib 入口，另一 Sol medium 独审。与 F005/F013 Mac 树不混补丁，不改 Harness F004、foreground、独立 set_value 工具或普通键事件。

明确结果类型区分 PatternUnsupported、ReadFailedNoInput、WriteAttemptedUnknown 和 Written。只有明确不支持且没有输入尝试时可走既有一次 fallback；GetPattern/cast 错误不能全部降为不支持，应区分 stale/缓存/其他错误。读旧值失败应 SetValue=0/fallback=0，真实空字符串是合法读取结果；写尝试失败及 worker/panic/cancel 保持 unknown，fallback=0，不能重输。已有写后读回失败也不得重写。生产 COM 调用必须实际采用纯事务及路由 helper，不能只测试一段未接生产的示例。

独立 Sol 另发现旧 from_raw 借 retained guard 的元素只在正常返回 mem::forget，panic 时可能释放借用 COM 之后再由 guard 释放。同包使用明确借用或 ManuallyDrop，先核 UIA 与非空指针，保持 guard 全程有效，不能以提前 return 绕过所有权处理。

Astra 核[微软 UIA 错误码](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-error-codes)及锁定 windows-rs 0.58 生成 wrapper：只有直接 GetCurrentPattern 的 UIA_E_NOTSUPPORTED（0x80040204）作为明确不支持。S_OK/null 被 wrapper 的 Type::from_abi 转为 Error::empty，其 code 为0，不可当成功或允许fallback；后续 cast 的 E_NOINTERFACE/E_POINTER 也都拒绝fallback。[接口转换实现](https://github.com/microsoft/windows-rs/blob/0.58.0/crates/libs/core/src/interface.rs)说明 QueryInterface 的转换边界。这是主源/锁定接口分析，未调用 Windows；保守拒绝null包装错误可能收窄旧fallback能力，不能为维持它误放行。

## 验收边界

注入 fake read/write/fallback 计数覆盖旧值读取失败、真实空值、非空中文换行追加、写失败、写后读回失败、stale 与 worker 错误，以及真正不支持的单次原路径。可在 Mac 编译运行纯 std 模块，Windows cfg COM 适配仍须 Windows compile 与现场实际加载验收；不自动安装 SDK/toolchain，不用 Mac 测试声称 Windows 编译通过。
