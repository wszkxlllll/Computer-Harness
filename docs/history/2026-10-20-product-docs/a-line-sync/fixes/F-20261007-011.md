## 实际发现

当前源码 FetchGlmHttpClient.post 的计时器只发Abort，fetch和response.json等待没有独立截止竞争或迟到检查。root直接以当前源码和内存fake fetch/body复现：local deadline10ms、body35ms返回且忽略Abort，最终resolve、请求信号已aborted，transport仍发body_received/success。没有真实HTTP、私有配置或密钥访问。

Astra medium独立核deadline5ms而headers/body35ms返回均误成功；忽略Abort的永久pending fetch在35ms后仍未settle，随后仅人工resolve合成fixture收尾；Run取消后迟到body也误记transport success。上层Adapter的Run signal检查可阻止该用户取消后的ModelTurn，但不能修正transport证据，也不能覆盖未取消上层signal的本地请求超时。

这证明客户端截止与取消合同缺口，不证明历史90秒真实API等待的服务端原因。原题180秒实交换仍待验收，不通过本测试宣称已恢复。

## 最小修复合同

F010完成冻结后，同一6.1 Sol medium作者仅修改packages/provider-glm/src/index.ts及对应测试，另一位6.1 Sol medium独审。单个总deadline覆盖fetch和body，取消/截止与等待结果竞争，每个await后再次检查；忽略Abort的异步结果不得无限拖住本地请求或成为迟到成功。首个取消来源及Run原reason保留，本地超时保持非retryable/feedback，未知远端请求不自动再发。

覆盖fetch/body迟到成功、永久pending、迟到拒绝、截止已过但timer未交付、预取消零fetch、Run与local取消竞争、正常成功及transport固定证据。只用fake HTTP，不改预算、超时配置、风险控制、GUI或模型请求次数。同步阻塞仍不能被JS抢占，本地settle和Abort不证明远端服务器停止处理。

## 验证与交接

唯一作者已完成总 monotonic deadline、独立 Abort race、派发前与 await 后守卫、首次取消来源和原 reason 保留以及 finally 清理。本地 timeout 仍 nonretryable / feedback；配置和默认值未改。完整 body 的 HTTP 成功证据是已经发生的事实；返回前已观察到取消或过期仍须拒绝，不能因此返回 payload。
