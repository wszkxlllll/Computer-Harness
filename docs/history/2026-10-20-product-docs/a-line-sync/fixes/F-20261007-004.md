## 已核范围

固定上游 CUA `cua-driver-rs-v0.22.2` Windows `platform-windows/src/tools/impl_.rs` 的历史代码审查显示：UIA `CurrentValue` 读取失败可退化为空串，再继续 `SetValue`；某些错误会被 `.ok()` 吞掉。该信息是上游源码风险依据，不是本机 Windows 故障复现。当前整合树没有 native CUA 源码，也没有安全注入旧值读取失败、同时证明零 SetValue/零 fallback 的接口。

固定上游审查来源：[`impl_.rs` Windows writer](https://github.com/trycua/cua/blob/cua-driver-rs-v0.22.2/libs/cua-driver/rust/crates/platform-windows/src/tools/impl_.rs#L4239-L4248)、[`action_target.rs` window-target normalization](https://github.com/trycua/cua/blob/cua-driver-rs-v0.22.2/libs/cua-driver/rust/crates/cua-driver-core/src/action_target.rs)、[`element_token.rs` element resolution](https://github.com/trycua/cua/blob/cua-driver-rs-v0.22.2/libs/cua-driver/rust/crates/cua-driver-core/src/element_token.rs)。前两份 core 源码的只读核查确认普通 window target normalization 不附带元素索引，缺少 element/token/index 时解析为无 UIA element；这是保持本仓现有 window-target serializer 路由的依据，不是原生输入效果验证。

## 最小处理

只阻断当前危险的 Windows UIA element-token/snapshot 多行后台派发：`executeMultilineType` 是该路径唯一 producer，调用 `type_text` 时附加 element token/snapshot 且 `delivery_mode=background`。在该派发前返回固定 no-input refusal；不调用 CUA `type_text`、`press_key`、`click`，不改走逐行按键或其他 fallback。

只读核当前普通窗口单行路径由 `actionRequest(type)` 产生 window-target `type_text`，参数不带 element token、element index 或 snapshot id；delivery mode 受现有配置与 window-binding 路由约束，并非一概为 foreground。本轮保持该既有 window-target 路径及其既有身份/几何/Surface/delivery 检查，不新增 UIA 单行能力。显式 UIA groundingRef 单行仍在前置校验即 `GROUNDING_ACTION_UNSUPPORTED`。该合同只说明本仓 serializer 的普通 window-target 请求不携带 UIA 元素定位符，不宣称所有 Windows 单行方式普遍安全或已通过原生验收。上游 0.22.2 源码审查中 `elem_idx=None` 与 element-index `Some(...)` 分流是该风险边界的依据；当前测试仅验证本仓生成的请求字段与 fake dispatch，不构成 Windows 原生行为证明。Darwin/Linux既有路径、DOM单行/受支持的独立路径、未知副作用不重放规则均不改变；不增加平台能力协议、不改上游驱动、不做桌面/API/服务操作。未来若引入 Windows 单行 element-token/index 或 background UIA writer，必须同样禁用直到旧值读取和 no-write 错误合同得到验证。

## 验收矩阵

- Windows UIA 多行：显式 grounding、自动唯一目标、grounding off/private resolution、LF/CRLF 输入都必须在任何输入派发前明确拒绝；`type_text`、`press_key`、`click` 计数均为0。grounding/refused/unknown 等不得绕过限制或触发替代 primitive。
- 普通 Windows 单行：保持现有 window-target 参数合同，无 element_token/index/snapshot_id；delivery mode 保持既有配置与 binding 约束。显式 UIA groundingRef 单行仍零派发拒绝。该测试不外推为所有 stock single-line 路由均已原生安全证明。
- Darwin / Linux 多行既有普通 window-target `type_text` 路径保持原合同；合成测试分别覆盖两平台的 LF/CRLF、完整参数对象中原样 text 与 foreground delivery、每次仅一次 `type_text` 且无 `press_key`/`click`，并确认不携带 element token/index/snapshot。不是 native driver 验收。
- 原 Windows UIA 多行用例均在新 refusal guard 后结束；此前这些测试中注入 fake driver exception/result 的下游分支现在不可达。本轮不声称仍覆盖原 native writer 或异常 fallback 分支，而以 refusal 与零派发断言覆盖安全边界。其他身份/陈旧观察/取消/未知回执相关保护不得放宽。
- 只跑 source-alias Vitest 与 scoped business noEmit，不构建或覆写共享dist；不把 fake 零派发称为原生 `SetValue=0/fallback=0` 故障注入，也不关闭Windows实机保存验收。
