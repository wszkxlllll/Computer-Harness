## SDK 窗口发现能力与边界

现有 SDK 路径可调用 `ApplicationSession.listAllWindowTargets`，但它返回的是 `projectWindowTargetInventory` 的目标投影，不是原始窗口层级快照。只有当某个 window ID 仍在该次投影中，才能将它与该行 PID 关联；projection 保留 PID、window ID、可选 app/title 和经过严格证明的 owner relation，不保留 `layer`、z、on-screen 或 alpha 等原生字段。这里的 `ownerPid/ownerWindowId` 表示父窗口关系，不能与 CoreGraphics row 的 `kCGWindowOwnerPID`（该窗口所属进程）混用。因此，若 1370/1391 在查询时已消失，返回列表不能回溯其 owner 或当时层级；缺席必须继续视为 unknown。

SDK 的 picker 查询通过 `CuaWindowDiscovery` 建立独立临时 driver/session，执行 list 操作后 endSession/shutdown/cleanup。尽管窗口列表调用本身是只读操作，临时 session 生命周期仍是运行环境操作；`ApplicationSession` 会在 active Run 时拒绝 list/activate，不能为了追踪窗口而与活跃 Run 并行开启 picker session。该公开 SDK projection 不足以提供同一 `bring_to_front` receipt 的 raw frontmost row 元数据。
