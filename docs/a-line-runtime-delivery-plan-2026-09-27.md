## 1. 本轮目标和边界

让用户从手机发起有用的任务，在电脑上得到可核对的成果；过程中能理解状态、追加要求、审批和停止，失败时知道原因和下一步。

先覆盖我们实际使用的一台电脑和一部手机，完成查询、文件编辑保存、跨应用整理三类任务。当前本机是 Mac，默认从 macOS 开始；手机系统及浏览器在开工时记录。Windows 历史输入和弹层问题单列，由对应设备复验，不用 Mac 的成功代替修复证据。

本轮必做的是核心任务和控制闭环。完整配置面板、回答偏好、Guard 策略编辑、长期记忆、三平台全部验证、18 个 Demo 和大规模对照实验均不作为完成条件。必要功能从体验中选择，没有问题就不为凑任务开发。

## 3. 首批任务：三题核心，一题可选

每题开跑前写清初态、目标、允许操作、停止点和结果核对方式。用项目自己的手机→Host→Runtime→Computer 链路完成；辅助桌面工具只用于诊断或人工准备，介入需记录。

| 任务 | 实际目标示例 | 完成证据 | 主要体验点 |
| --- | --- | --- | --- |
| T1 查询与比较 | 在实际可访问的公开商品页比较三款笔记本：预算内、至少16GB内存，列出价格、重量、来源和不满足条件的项；只查询 | 与当时页面核对型号、数字和约束，注明来源与时间；未知项如实说明 | 搜索、滚动、标签切换、约束保持、结果可读性 |
| T2 编辑与保存 | 在 TextEdit 或实际编辑器中创建一份中文出行清单，包含日期、数字、标点和多行文字，保存到专用目录的唯一新文件并重新打开 | 文件存在、内容逐字一致、可重新打开、保存位置明确 | 中文输入、焦点、保存弹窗、结果交付 |
| T3 跨应用与纠正 | 将 T1 信息整理成文档；过程中通过手机追加“预算降低，只保留符合新预算的结果”，另存新文件 | 新要求生效、旧方案不继续执行、来源保留、文档内容正确 | 手机纠正、切窗、长任务状态、跨应用保存 |
| T4 可选：准备草稿 | 使用测试邮箱或会话，准备正文与合成附件，停在发送前 | 收件对象、正文和附件正确，无发送 | 草稿、附件、审批解释 |

T1 可在首次运行前换成真实出行查询或医院服务信息查询；冻结实际可查日期、预算和来源。需要验证码时交由用户处理；环境不可达记录为阻塞，再选同类任务，不能计成功。

T2 优先普通文本编辑器，T3 再按实际需要选择 WPS/其他办公软件。避免一开始就把所有办公软件适配列为必需。

T3 如果需要显式人工切窗，先记录辅助完成及原因，再评估通用修复。T4 仅在前三题稳定且确有使用需求时增加。

## 4. 第一晚：先拿到实际体验

建议预留 2—3 小时；这是时间盒，遇到环境问题据实调整。

| 时段 | 工作 | 应得到什么 |
| --- | --- | --- |
| 前30分钟 | 核对版本、依赖、驱动、必要 Mac 适配、手机配对和目标窗口；准备测试文件目录 | 可启动的真实链路及简短环境记录 |
| 接下来20分钟 | 简短本地任务验证截图、取消、暂停恢复；检查已知未知副作用重复路径的保护 | 明确可以试哪些操作，有安全阻塞先修 |
| 接下来50分钟 | T1、T2 各试一次 | 实际结果、人工介入、最卡的一步 |
| 接下来40分钟 | 能继续则体验 T3，否则定位前两题阻塞 | 最多3个优先问题 |
| 最后20分钟 | 按影响选择修复项，安排下一次复测 | 一份短清单和逐项完成标准 |

无需先开发有效配置页面。现有日志/报告能解释配置就先用；缺信息影响判断时补最小诊断。

真实操作前一次确认本批桌面目标、独占时间和模型请求预算；同批范围内持续执行，不逐步重复询问。预算按当时账户情况确定。本计划本身不启动付费调用。

## 5. 后续循环：一轮处理一个主要问题

固定流程：真实体验→定位问题→最小修复→原题复测→同类变体→登记结果。

1. 先看真实成果，记录哪里要猜、等、反复点或手工帮忙。
2. 判断问题属于环境/网络、模型决策、输入/窗口、审批/控制或界面反馈；证据不足保留未知。
3. 用最小场景复现。驱动问题先用无模型探针，避免整题反复消耗额度。
4. 修改最小必要范围，优先复用已有状态、事件和接口；不为单个网站写固定坐标或答案。
5. 跑相关回归，再用新 Run 复测原题，保留失败记录。
6. 改日期、文本、预算或文件名复验，检查是否只对原题有效。

同一错误连续两次出现就转诊断，不盲目重跑整题。每轮最多集中处理1—2个问题。原题失败不能通过放宽其目标“修复”。

## 6. 哪些必须修，哪些按需做

| 优先级 | 问题 | 处理 |
| --- | --- | --- |
| 立即处理 | 错窗输入、拒绝后仍执行、审批重复消费、取消生效后继续派发动作、未知副作用被重复执行 | 暂停受影响链路，补保护和回归后再试 |
| 核心阻塞 | 无法配对、中文输入错误、保存失败、关键弹窗不可见、纠正丢失、结果假报完成 | 当前主要修复范围 |
| 明显体验问题 | 不知道等什么、找不到文件、审批理由不明、回复难读、无意义重复 | 体验后选最影响使用的1—3项，按需补齐 |
| 后续优化 | 全配置面板、长期资料、完整 Guard 编辑器、全平台测试、模块研究 | 暂缓；只有核心任务证明其必要性才纳入 |

### 候选功能与停止范围

| 触发体验 | 最小交付 | 边界 |
| --- | --- | --- |
| 长时间无反馈 | 区分执行中、等待模型、等待用户、暂停、已停止，显示最近有效进展 | 不造无法计算的完成百分比 |
| 不知道结果在哪 | 显示文件名、保存位置、来源和未完成项；已有下载入口可接通 | 需要新权限合同的下载能力单独估量 |
| 审批难理解或批准后没反应 | 具体动作与原因、绑定截图、命令与执行状态清楚 | 不要求开发整套 Guard 设置 |
| 手机与 TUI 行为不同难定位 | 来自真实 Run 配置的只读摘要 | 不预先开放全部开关 |
| 回复详略/语言持续不合意 | 必要时把现有偏好字段校验、冻结后送入 Context | 不做跨设备同步和自动学习 |
| 重复滚动或操作 | 根据证据修观察、错误语义、有限恢复提示 | 不同时改多个模块默认值 |
| 断网回来状态不明 | 恢复状态和命令回执，说明继续、已停或需新任务 | 不承诺 Host 重启后无损续跑 |

有必要传递偏好或某个运行选项时，只做对应白名单、默认值和每 Run 冻结；无需等待完整配置页面。每个新字段都要有实际消费者及关闭/重置后的行为。

## 7. 穿插完成最小控制验证

用无外发的本地任务验证手机和真实 Computer 的控制链路：

- 批准一次，对应动作恰好执行一次；重复点击不重复消费。
- 拒绝后该动作零执行；任务可以按允许范围重新规划。
- 等待审批时取消，旧批准不再生效；纠正使旧请求失效。
- 暂停生效后不派发新动作；恢复按最新要求继续。
- 手机短暂断网后能确认状态，不重复创建 Run 或重放动作。
- 截图对应正确目标及审批请求，旧图不冒充最新状态。

区分命令已收到、控制已生效、动作已发生。取消不回滚已完成的动作；执行中取消若效果不明，报告未知并停止继续派发。

普通本地任务若不触发审批，可用明确标记的测试策略要求审批，验证真实执行链；这只证明控制机制。生产 Guard 的识别效果用本轮涉及的正常/需确认案例补查，不能混为同一证据。

## 8. 设备问题与故障处理

整段输入错误：对照实际字符串、驱动参数、输入法、目标控件和最终文件。先定位或限制受影响能力；逐字输入只作为待验证候选，不自动当所有平台通用修复。

窗口/弹层异常：区分输入前明确拒绝与输入后结果不明。后者停止重复动作并核对状态；保持精确目标和重新观察，不静默扩大到整桌面。新窗口按现有确认交接合同处理。

平台能力阻塞：做一次有界诊断，给出可用替代路径和限制。长期底层驱动问题单列，不能无限消耗整轮时间；若因此无法完成核心任务，明确部分交付并与用户调整范围。

## 10. 排期与费用控制

先安排4—6次工作时段，每次约2—3小时，中间可以编码和跑离线检查。首轮之后再估剩余工时，不预先承诺解决未知底层故障的日期。

| 时段 | 重点 | 输出 |
| --- | --- | --- |
| 第1次 | 启动、控制冒烟、核心任务首跑 | 可用边界和优先问题 |
| 第2—3次 | 修阻塞、原题复测、控制检查 | 至少两类任务能完整完成 |
| 第4次 | 跨应用与纠正，补必要体验功能 | 三类任务的可重复路径 |
| 第5次 | 独立重复、同类变体、短时断网 | 稳定性证据和剩余限制 |
| 第6次（需要时） | 队友试用、整理和交付 | 别人能照说明完成任务 |

每题可预算首次体验、修复后复测和一个变体，三题约9次起步；诊断和控制测试另计。没有代码修复时，第二次就是独立重启后的重复。次数是估算，不是成功门槛。

每批设置模型请求上限，记录 Provider usage、总耗时、人工等待和介入次数；从现有事件汇总，缺必要数据再补。禁止无目的反复跑失败题。

## 11. 什么时候算完成

完整交付同时满足：

1. T1、T2、T3 各有一次完整成功和一次从可复现初态开始的独立复验；每类至少覆盖一个变体，成果均核对。
2. 至少 T1/T2 在初始准备后无需手工代做关键步骤；正常审批、澄清和通过手机纠正属于预设交互。临时指点坐标或代做步骤记为辅助完成。
3. 第7节控制检查通过，没有未解决的错窗、重复副作用或取消/审批失效问题。
4. 本轮选中的必要补齐项实际生效并复测。未选择的可选功能不影响收口。
5. 版本、配置、三张任务卡、成果索引、启动说明和已知限制齐备；另一位队友至少按说明试用一题。

T3 若只能人工交接关键窗口，标记“基础任务可用，跨应用辅助完成”；不能直接报告完整 A 线完成。设备限制导致核心范围需要缩减时，由用户确认调整后收口。

可以保留一段完整内部演示录像，不强制多份 Demo。录制使用测试资料，原始私密截图与轨迹保留本地忽略目录。

## 12. 最少记录与交付要求

每次一行：日期｜代码及运行配置｜任务/Run ID｜完成/辅助/失败/阻塞｜真实成果｜人工介入｜主要问题｜下一步。关键失败附本地证据索引。

每个修复的说明包括：用户遇到什么、改了什么、原题/变体结果、仍有哪些限制。相关测试覆盖实际错误边界；涉及共享 Runtime、协议或 Host 时跑相应集成及全量回归，合并前遵守仓库构建测试要求。普通文案小改用针对性检查。
