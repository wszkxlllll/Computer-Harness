# 真实生活任务案例

Lightspeaker围绕六类生活场景设计任务，并通过真实Harness在实际网站和桌面应用中测试。本文集中说明需求、操作内容和证据位置，不把候选题、来源预检和实际执行混为一谈，也不汇编不同版本的总体成绩。运行记录用于推进开发和体验完善。

## 代表案例 为长辈查车次并发到微信

用户需要的不是一页车次搜索结果，而是一份容易阅读、能够直接交给家人的乘车信息。代表流程是在携程查上海出发、指定日期和时段的直达车，比较两班车次、时间、历时及二等座信息，整理成中文文字，再发到明确授权的微信会话。

任务从指定网站和已有受管登录状态开始，不使用预填答案。用户在手机交代需求，电脑在浏览器里查询；如果条件需要调整，用户可在同一Run中纠正。接着Agent查找并激活微信，确认文件传输助手，写入内容；需要发送审批时等待用户决定，执行后从新画面核对本次消息。

这条流程体现浏览器与原生应用之间的连续任务、当前画面核对、用户纠正和发送前控制。录制使用测试会话及可公开文字，车次日期随录制日冻结，等待加速明确标注。正式双端视频尚待重录，旧开发素材不作为成品嵌入。

既有电脑验收从已登录和已准备的表单状态开始，包含人工日期纠正和审批；不是从未登录状态全自动完成，也没有手机画面或音轨。正式重录会补齐真实手机交互，不用后期模拟替代。

既有动作与新消息证据见[跨应用记录](./history/2026-10-20-release-convergence/life-business-evaluation-2026-10-15.md#2026-10-20-跨-app-demo-收敛与验收)。早期南京路线题与后来收敛的车次发送Demo题面不同，各自记录，不替换旧结果。

## 六类场景怎样落到任务

| 场景 | 自然需求与实际操作 | 使用入口与准备 |
| --- | --- | --- |
| 政务与公共服务 | 家里老人准备办理敬老卡，查本人和家人代办所需证件、领取后是否需另行激活金融功能。Agent阅读政府/民政公开说明，整理步骤及来源。 | 上海市政府、民政官网；公开信息不要求输入身份证或操作银行账户 |
| 就医与健康服务 | 长辈不熟悉智能手机，了解华山医院电话预约、到院材料和取消方式；另有就诊资料整理任务。 | 医院官方公开说明、浏览器及任务需要的编辑器；不真实预约、取消或拨电话 |
| 购物与售后 | 在中国大陆Apple Store实体店购机后，了解退货材料、地点及运营商协议处理。Agent查指定渠道政策并说明。 | Apple官方政策；不查私人订单、不发起售后或联系商家 |
| 出行与票务 | 为阅读小字困难的长辈比较车次或接驳，整理后发给指定微信会话。 | 携程、高德及微信；需动态核对日期、查询结果和精确会话，发送依明确授权和审批 |
| 生活缴费与社区服务 | 根据官网公开价格，帮助理解示例燃气账单、阶梯区间和费用构成，或整理社区事项材料。 | 官方价格说明及本地示例账单；示例输入不伪装成真实账单，不进行付款 |
| 通信日程与个人资料 | 阅读指定版本日历官方手册，说明重复日程与提醒的设置方法；在编辑器整理文本并交付。 | 官方帮助页面、受控文档和应用；读取手册不等于已在用户日历创建事件 |

上述六类均有真实Harness尝试。每次实际做到了哪一步、用过哪些工具、留下什么画面，以对应轨迹和逐次记录为准。任务不是全部网页问答，也不强迫每题跨应用；跨应用用于确实需要交付或应用协作的需求。

## 任务如何推动产品改进

实际使用暴露的输入异常、保存时的焦点变化、相似窗口、过期引用、无效重复和审批交互，分别进入底层适配、Runtime、Context与手机端改进。比如跨应用案例必须区分历史相似消息与本Run新发送的内容；编辑任务则需区分输入回执和最终可见文本。

人工纠正保留原文、接收及实际消费时间，不把未消费的反馈算成有效介入。Plan、Memory和Monitor按运行配置记录，工具调用本身不作为效果证明。任务日期、登录状态、模型和采集开关变化时，保留新的运行记录，不覆盖旧文件。
