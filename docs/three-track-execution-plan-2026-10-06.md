## 4 批次 1 完整双预算并证明模型请求发出

优先级最高。负责人：（8）整合，（6）复审，（10）部署与手机取证。

拟修改文件按依赖一起引入：

- `apps/host/src/glm-output-budget.ts`、`index.ts` 与对应测试：默认值、显式配置、范围校验和有效配置输出。
- `packages/app-runtime/src/config.ts`、`providers.ts`、`run-factory.ts`、`reporting.ts`、`remote-run-api.ts`：将配置传至真实启动入口并保留错误诊断。
- `packages/context/src/compiler.ts`、`packages/runtime/src/contracts.ts`、`packages/protocol/src/index.ts`：文本选择预算与 wire 预算各自传递。
- `packages/provider-glm/src/index.ts` 与相关测试：Provider 投影后按文本、视觉、外壳计费前估算，准备阶段显式拒绝越限请求。

执行顺序：先移植上述完整依赖组，核对显式环境/CLI 配置是否仍覆盖为旧值；再用真实 Context→GLM Adapter、假 HTTP 做边界回归，验证旧预算拒绝且零 HTTP、新预算接受且一次 HTTP。保留未配置 wire 时原有回退语义，验证非法值、text > wire、必要上下文放不下的错误。不能以删任务正文、丢最近 GUI 结果或全局加大超时通过。

离线通过后，（10）接收冻结源码并核对源码→构建→进程→手机页面四类证据。手机在明确的新空白测试窗口启动短中文任务；若已知候选预览阻断，先在批次 2 完成对应必要修复，再回到此验收。保留原始任务要求，不用容易通过的缩短任务冒充原题复验。

通过条件：记录生效的两个预算和估算组成，`prepare` 成功；Provider 有实际 HTTP 响应状态或可核对的请求/响应交换证据，并与同一 Run/request 关联。`model.request.started` 单独不算网络已发出。模型返回的后续 GUI 或保存失败分别归因，不推翻已证明的预算结果，也不宣布任务整体完成。HTTP 已进入但超时记录为独立 Provider 问题。

本批成果是一组可构建提交、一份独立预算复审和一次手机真实网络证据。现有 16384/24576 是 PR24 的默认值，不预先认定适配所有任务；修改任何新上限须有实际估算和所用模型约束依据。

## 5 批次 2 修复候选预览和执行能力

这批先定位真实失败，再冻结最小修复范围。四个工作包可以并行调查，共享文件串行整合。

### 2A 候选准入与真实预览

涉及 `packages/app-runtime/src/remote-run-api.ts`、`packages/computer-cua/src/window-discovery.ts` 及其调用的捕获路径、`apps/host/src/server.ts`、`apps/relay/src/server.ts`、`apps/web/src/HomeScreen.tsx`、`components/WindowTargetPicker.tsx`、`PendingRequestPanel.tsx` 及现有测试。仅在实际合同变化时同步协议，不新建一套预览服务。

1. 测试方复现一次真实手机预览失败，串联手机→Relay→Host→Runtime→CUA 的 request/candidate、失败阶段、脱敏错误码、分段耗时、取消来源、响应状态、PNG 字节和图片解码结果。不得输出 token、图片正文或私人窗口信息。
2. 区分排队、session 初始化、前置精确身份、截图缺失、图片无效/过大、后置身份变化、会话清理、传输和页面解码。统一 catch 保留内部可追踪的原因，对手机给可操作说明；诊断一次后进入命中环节的修复，不能无限追加探针。
3. 8 秒外层与 20 秒捕获上限先按实际剩余时间分析。确为排队/截止问题时再统一截止、及时取消和有界清理；身份验证成功但无图片必须判预览失败，不能给确认凭据。
4. 初始列表和运行中交接列表同时修准入。精确身份相同的重复行可规范化；同身份信息冲突须重新取证。不同身份的同名窗口保留各自预览与实际可辨识信息；缺标题不能单独成为排除依据。无关系统对象和没有可操作路径的对象不进入可确认候选；无法确定的情况明确提示刷新或改选，不伪装成可操作。
5. 保留 candidate-bound previewToken、过期、撤销、刷新和运行终止校验。失败后可重试当前有效候选、刷新或退出；有模态阻挡时不能用“跳过”绕回父窗输入。

通过条件：两个真实同名文稿可分别预览并选中，各自目标正确；无关枚举对象不占交接列表；关闭窗口、先预览 A 再刷新/选 B、旧请求迟到、并行预览、图片加载失败、取消和撤销设备均不误确认或创建重复任务。一条曾失败的真实请求在修复版成功，并能解释之前失败发生在哪一段。

### 2B Mac 能力匹配与保存 sheet

涉及 `packages/computer-cua/src/macos-target-topology.ts`、`cua-driver-computer.ts`、相应测试和现有 Runtime handoff 管线。只有真实保存路径证明确需原生能力时，修改 `native/cua-driver-macos-topology-v1/` 对应实现、镜像、注册 patch 和 hash 清单；停止增加与生产任务无关的 TextEdit 探针。

初始化时按实际 driver/session 协商能力并固定选择，驱动替换或 session 重建后重新识别。私有 topology 留在 Adapter 内；stock CUA 没有私有 RPC 时仍支持其能够证明的精确目标基本操作。能力缺失不等同身份变化，不能每步按 darwin 强制私有 RPC，也不能缺接口后暗中切成全桌面操作。

| 动作后所见事实 | 应实现的结果 |
| --- | --- |
| 新对象已证明无关，当前目标身份和该动作所需焦点证据有效 | 更新观察，继续当前目标；不因任意新 CGID 全部失效 |
| 可操作弹窗有充分关系与身份依据 | 经现有 Surface/切窗规则进入弹窗，取得 fresh observation，再生成新动作 |
| 弹窗可精确展示，但自动归属证据不足 | 发真实 `waiting_window` 请求和候选；手机明确确认后继续，不只抛“手动处理”文字 |
| 可能存在模态阻挡，无法建立可操作目标 | 冻结依赖该证据的输入，展示具体缺口和退出方式；不得继续向父窗输入 |
| PID/原生身份重用、代际或绑定真实变化 | 失效旧引用并要求重新绑定；保留已完成回执 |

保存 sheet 可能没有独立 CGID，需要现有父 Surface 下的可辨识 child/overlay、有效交互范围和观察，不强求它出现在顶层列表。完成保存后按有效关闭/父窗证据返回正文；不能凭不完整清单里“没看到 child”推断它已关闭。独立只读会话的严格创建条件不变成所有用户窗口的操作前提。

必须覆盖的反例与正例：stock CUA 基础精确窗口成功、增强接口可用、能力缓存随 session 失效、无关新窗、同名不同窗、真正身份变更、有/无独立 CGID 的保存界面、未知关系、child 关闭与父窗恢复，以及 completed 后观察失败不重放。生产 Harness 必须能走到 sheet 输入与确认；只读两张图不能关闭本工作包。

### 2C Windows 和 Linux 的共享条件

由 `cua-driver-computer.ts` 唯一写入者统一处理非 darwin preflight。取消“全局 inventory 不完整就拒绝所有基础动作”的条件；仍核对精确目标、前台、几何、新鲜观察及动作相关阻挡。真实库存读取失败和证据不足按所影响的能力分类，不能当作完整成功。

关系推断、自动 child 准入、窗口消失和恢复父窗继续使用它们需要的证明。Windows/Linux 离线测试覆盖不完整库存下基础动作可行、目标缺失拒绝、错误前台零输入、未知副作用不重放、关系不足不能自动切窗。Linux CI 只证明合同，未运行 Linux GUI 时明确未验收。

### 2D Windows 中文追加保护

先针对固定驱动复现 `CurrentValue` 失败后继续 `SetValue` 或 fallback 的路径。驱动在同一受控操作中区分“不支持此输入模式”和“旧值读取失败”；后者在任何写入前终止并明确 no-input，不能先转空串。已尝试写入后的读回失败保持 unknown，不得换路线重输。

拟修改 Harness 的 Windows 多行入口和测试；如需原生修复，在固定上游 Windows `libs/cua-driver/rust/crates/platform-windows/src/tools/impl_.rs` 路径形成可复现补丁，并登记实际打包/加载产物。具体补丁存放位置在实施交付中声明，不改 Mac overlay 来伪装 Windows 已修。升级 0.33.1 不自动解决这项风险。

通过条件：故障注入同时断言 SetValue=0、fallback=0、原文不变；非空正常追加、中文多行、选区、末尾换行、取消、过期元素和写后读回失败分别验证。未取得修复驱动时，可暂不开放未证明安全的追加路径并如实标限制；不能据此宣布 #22 的追加能力已验收。预算请求取证可以先行，但该平台输入闭环和发布承诺不得绕过此风险。

| 平台 | 正式链路 | 成果核对 |
| --- | --- | --- |
| Windows | 手机→记事本新文稿→完整中文多行→保存弹窗→唯一新文件→返回正文→关闭文稿→重开 | 文件位置、编码、全部字符、标点、数字、换行和重开画面；既有文稿与其他窗口无改变 |
| Mac | 手机→TextEdit 新文稿→纯文本与完整中文多行→保存 sheet→唯一新文件→返回正文→关闭文稿→重开 | 同上，额外确认实际不是 RTF、sheet 可输入可关闭、返回父窗观察有效 |

正文沿用[A 线计划第 13 节冻结 T2 任务卡](./a-line-runtime-delivery-plan-2026-09-27.md)的完整六行、基线/独立复验/变体，日期数字是测试数据，不因当前日期而擅自改写。每次在该机器新建专用目录和唯一文件名，不复用历史临时路径或覆盖已有成果。Win 换行/BOM 预期在开跑前冻结并分别检查：中文正文须逐字一致，UTF-8、行结束符和末尾换行另列；若要求原卡逐字节 LF，则须明确达到该要求，不能事后静默归一化为通过。

每平台三次正式完整任务：一次基线、一次全新初态独立复验、一次冻结变体。相同 SHA、依赖和任务参数的独立复验可以共用部署，不重复扫码。不足三次时记录已通过的部分，不宣称稳定验收。测试失败保留原文件和差异，先归因，再在修复版本开新 Run；未知副作用不得重复旧保存或输入动作。

退出条件：三份可重开的真实文件、对应 Run/保存/重开记录和只读内容核对一致；模型、GUI 回执、文件成果和手机终态一致。出现保存框、返回 completed 工具回执或屏幕有正文均不能单独算成功。

## 7 批次 4 跨应用和手机控制

先按用户本轮要求跑携程→编辑器：Windows 为携程→记事本，Mac 为受管浏览器携程→TextEdit。实施前冻结可访问公开页、查询日期/路线、初预算和降低后的预算，只查询、不预订；遇网站登录或验证码，由用户完成必要认证并记介入，不能代填采购或付款。若实际网站不可达，记录环境阻塞，不用合成网页宣布携程已通过。

该场景承接原 T3 的完整验收维度。原 Apple T3 留作历史基线，不强制同时再跑两套跨应用题；本轮携程任务卡须保留来源/时间、原始比较信息、至少一次真实跨应用切换、途中手机降低预算、旧请求失效、按新要求生成结果、唯一新文件保存与重开。Mac/Windows 的目标引用和切窗都由 Harness 的显式能力完成；人工代切关键窗口只记辅助完成。

每平台仍按基线、独立复验、变体三轮核对跨应用结果。没有满足新预算的项时明确写无符合项；未知价格不能当合格推荐，最新网页证据不能被旧 Run 记忆替代。纠正后不得继续执行旧请求或重放已经发生的输入。

T1 已有完整成功一次、独立重复失败的历史记录。恢复后的最终组合版本补原 T1 的完整基线/独立复验/变体缺口，观察是否仍重复滚动耗尽额度；不要靠提高请求次数掩盖无进展。若本轮将出行查询作为 T1 场景，须在任务卡明确对应字段与约束，不能拿短预算冒烟代替完整查询比较验收。

控制检查尽量并入以上 Run 和代理可操作的测试页面：一次批准只执行一次、拒绝零执行、审批中取消、纠正使旧请求失效、暂停后无新派发、恢复使用最新要求、页面刷新和连接恢复不重复执行。真实手机触摸、物理网络切断和移动端显示由用户完成；最后由另一位队友按启动说明至少独立完成一题。

## 8 用户需要参与的最小范围

代理先完成版本部署、离线反例、桌面准备和非手机专属检查，再给用户一张本批任务卡。每次交接说明页面、目标窗口、预期结果和停止条件；用户不负责反复提供相同失败截图或盲选编号。

| 时机 | 用户操作 | 计划次数 |
| --- | --- | --- |
| 恢复某台 Host 的手机连接 | 必要时扫码和本机批准；已有配对有效则直接复用 | 每台 Host 每个有效配对周期 0 或 1 次；不因修复迭代主动清配对 |
| 双预算真实验收 | 在已准备目标上从手机启动任务 | 每个平台先 1 次；成功且版本不变可计入后续同题基线，不重复报成果 |
| 同名候选真人确认 | 查看真实预览并确认目标，两个同名窗口分别验证 | 每平台一组 2 次选择；代理先证明预览工作，避免用户连续失败重试 |
| T2 与 T3 | 启动已冻结任务，T3 在指定节点提交一次纠正；正常审批按产品提示 | 每平台 T2 三轮、T3 三轮；代理能完成的轮次由测试方执行，手机专属轮次集中交接 |

| 外部前置条件 | OS 锁屏解锁、权限批准或网站验证码 | 仅实际出现时一次处理并记原因，不用人工代正文或保存 |
| 队友试用 | 依文档启动并完成一题 | 至少 1 人 1 题 |

这里给的是验收任务次数，不保证每轮只需一次按钮操作。若同一构建持续出现同因错误，测试方一次充分取证后交修复，不要求用户反复扫码重试。Windows 机器暂不可用时仍可推进 Mac，Windows 状态写“待现场”，保留 main 放行边界。

## 9 批次 5 独立审查与远端交付

最终组合版本先跑定向边界和跨模块检查，再执行 `pnpm run typecheck`、`pnpm test`、Web build，以及原项目要求的 CLI/原生相关检查。原生有修改时校验固定上游、patch 重放、镜像和 hash，并实际编译对应平台产物；TS CI 不能证明 Rust overlay 或 GUI 已验收。测试通过后不为累计次数重复跑相同套件。

## 10 失败归因和回退

| 首个可靠证据 | 归因与下一步 | 不能怎样处理 |
| --- | --- | --- |
| prepare 报 wire 超限，HTTP 未进入 | 核对有效预算、Context/Provider 合同及实际部署版本；修预算传递 | 延长网络超时、减少任务正文来掩盖 |
| HTTP 已发送，响应头或正文超时 | 保存阶段耗时和响应证据，独立跟踪 Provider；按当前任务状态决定新 Run | 记作同一个预算错误、无条件自动重试 |
| 预览失败有具体阶段 | 修对应排队/身份/截图/传输/解码分支；同版本最多先取一条充分失败轨迹 | 先猜超时、解除预览绑定让用户盲选 |
| 精确目标可用但增强能力缺失 | 选择基础能力；仅冻结依赖缺失证据的自动准入 | 全局拒绝全部动作、伪造完整性 |
| 可识别弹窗未进入接管 | 修现有 handoff/Surface 路由并验证手机继续 | 用错误文字当“已支持手动接管” |
| 旧值读取失败 | 证明零写入、零 fallback；记录驱动拒绝 | 将空串当旧值继续输入 |
| completed 后观察失败或结果 unknown/partial | 保留回执，冻结后续相关输入；只读取证并生成新的决策边界 | 重发旧 action 或旧 batch 后缀 |
| 文件不存在、字符/编码不一致 | 保存原文件和差异，定位输入/保存/格式/重开阶段 | 测试脚本修文件后计通过 |
| 页面、Host 或驱动版本不符 | 记 `version_mismatch`，结束在途 Run 后由测试方重新部署 | 关闭源码 issue 或累计有效复验 |
| 锁屏、权限、机器或网站不可达 | 记环境 `blocked` 并给必要人工动作；其他独立工作继续 | 宣布代码修复失败或任务成功 |

回退以冻结的上一组源码、依赖、驱动和 Web/Host/Relay 构建为单位。先结束 Run、确认无输入在途、发布 `test_released`，再由测试方切回；保留失败版本的日志和输出文件，不删除或重写成果。输入结果未知时只读核对现状，不靠回退重放旧动作。涉及数据覆盖、错窗或重复输入立即停止该路径，其他不相关工作可继续。

## 11 CUA 性能优化的启动条件

当前批次需要的能力匹配、预览与保存修复先做。上游完整升级及纯性能优化遵守用户此前排序：当前 A 线测试批次结束并释放现场后，另立版本对照，不能插入正在验收的运行版本。

候选版本沿用既有审查的固定 0.33.1 及关联修复，但启动时再核对适配范围。检查 npm SDK、原生 driver、Node addon/动态库、工具参数、图片格式、回执、错误和清理的一致性；本地 Mac 扩展单独移植与验证。优先评估完整兼容升级，不兼容时才评估带依赖的最小补丁回移。

用同一平台、同一目标、同样配置记录改前/改后分段耗时和失败率，区分冷启动与热路径。样本不足只报告样本，不声称稳定 p95 收益。Windows 的精确窗口查找和换行修复不作为 Mac 性能证据；截图缺失与旧值读取失败仍独立关闭。无可靠收益或出现兼容回归时保留原版本，不扩大原生探针或把版本号本身当成果。
