# Mac 跨窗口与弹窗能力补齐执行计划

日期：2026-10-03。状态：待实施；本计划不代表已开发、已部署或已验收。

目标是让手机发起的任务在 Mac 上完成“受管浏览器查询 → TextEdit 整理 → 必要弹窗处理 → 返回继续 → 如实交付结果”。先补实际任务必需的能力，不以支持所有软件、所有系统弹窗为完成条件。无需配置 Jev API。

## 当前基线和放行范围

依据[跨平台专项复审](./cross-platform-window-popup-review-2026-10-03.md)及最新协作记录：

- 基线提交 `abb54b2` 已有显式列窗、切窗、稳定 ComputerSession 和 Surface 代次机制。Windows 有只读关系 probe；Mac/Linux 尚无等价生产者。
- 最新工作树包含 [F014](./a-line-sync/fixes/F-20261003-014.md) 的单窗口 handoff 能力合同修复，尚未提交。执行前须重新冻结实际源码及指纹，不能只记录 HEAD。
- [T023](./a-line-sync/tests/T-20261003-023.md) 记录单窗口点击、刷新焦点、一次短中文输入及截图核对成功，随后最终模型请求等待响应头 90 秒超时，Run 仍为 failed。它不是跨窗口通过，也不是输入失败。
- 上轮本聊天的 335 项离线测试针对修复前审查基线；F014 的 1471 项 Vitest、71 项 TAP 来自修复方报告，本计划编写时没有重跑。
- 当前计划可用于安排实现。实机操作、模型额度、服务重启、推送合并按原有权限与三聊天协调执行，本计划不扩大授权。

核心必做：普通窗口往返、TextEdit 单行与多行输入、常见菜单关闭、打开和保存 sheet 的取消返回、错误与人工接管反馈。唯一新文件保存作为最终业务验收，需限定专用目录、不覆盖。

首轮不做：个人浏览器 DOM、任意第三方软件弹窗全适配、系统权限弹窗自动批准、跨 Spaces/全屏自动操作、剪贴板全局替换、Windows/Linux 新能力开发。多屏和缩放列为独立兼容验证，不能用单屏结果宣称支持。

## 六个阶段

| 阶段 | 交付内容 | 人工配合 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| 一 基线与最小复现 | 当前运行版本、能力样本、失败层级 | 关闭敏感窗口，准备空白 TextEdit，检查系统授权 | 确定窗口身份及缺失证据；测试环境可独占 |
| 二 Mac 只读 probe | 可验证的本机窗口和弹窗关系证据 | 手动打开菜单、sheet、切换焦点供采样 | 受控样本有精确证据，未知情况明确拒绝 |
| 三 跨窗口接线 | 浏览器与原生窗口双向操作闭环 | 确认可见落点，不替模型输入 | 两种起点往返及安全反例通过 |
| 四 弹窗生命周期 | 菜单、对话框、sheet 出现和关闭后恢复 | 观察弹窗归属与恢复位置，必要时取消 | 每类支持弹窗独立通过，不误点父窗口 |
| 五 文本与保存 | 中文多行、内容核对、唯一新文件保存 | 逐字核对及确认限定保存范围 | 内容不重复、不串窗、可重新打开 |
| 六 手机端到端与发布 | 完整实际任务、版本与验收记录 | 手机配对、发任务、一次纠正与停止验证 | 实际成果和任务终态一致，独立审查通过 |

顺序为一 → 二 → 三 → 四 → 五 → 六。阶段一可先检查已有切窗能力；证据不足立即记录，不反复调用模型撞错。最终模型超时问题由原修复线并行处理，阶段二至五先使用无模型的确定性测试，不因此停摆。

## 阶段一 核对版本并建立最小样本

实施工作：

1. 读取最新 fixes/tests，确认无实机 Run 和输入在途。测试方预约共享环境，记录 Git HEAD、dirty 文件范围和源码指纹、构建时间、Host/CUA 版本及进程、手机资源版本。对 F014 及后续修复先做单窗口回归，不重复实施已修问题。
2. 记录 Mac 系统、芯片、显示器缩放、CUA SDK/daemon 版本及对应进程的辅助功能和屏幕录制权限。权限由用户在系统设置授予，不由代码绕过。
3. 准备受管浏览器的本地测试页和新建未保存 TextEdit 文档，使用合成内容。不使用个人浏览器、已有文件或硬编码坐标。
4. 先做只读枚举和精确截图，采集顶层窗口、菜单、sheet、焦点变化后的结构化样本。用同一原始响应验证现有解析器有无丢字段，避免本来 SDK 已提供而重复实现。
5. 在已授权范围内做一次无模型的 browser → TextEdit → browser 往返，分别定位 activation、capture、inventory、post-action detection、DOM 恢复问题。输入仅在精确焦点成立后执行。

人工验证：打开空白 TextEdit 并保留一个受管浏览器；需要时手动弹出菜单或打开/保存对话框。采样与自动操作分时进行，自动操作期间不要移动鼠标或抢焦点。

交付：版本表、脱敏样本、失败最小复现、可用能力矩阵。任何真实窗口内容留本机，入库 fixture 使用合成标识与文本。此阶段不要求完整模型任务成功。

## 阶段二 实现 Mac 只读关系 probe

先做可行性验证，再确定实现，不承诺把 Windows HWND 合同直接复制到 Mac。

1. 优先复用 SDK 已有的可信结构化字段。若不足，再依据 Apple 官方资料核对 Accessibility 与公开窗口枚举接口的能力，评估小型本机 helper 或 SDK 扩展；具体语言、打包方案在样本证明后冻结。
2. 首要技术门槛是精确关联 CUA windowId、系统窗口身份、AX 元素及其父子关系。应用名、标题、相似坐标、同 PID、单一焦点应用均不能独立证明同一窗口或归属；不得使用私有 API 作为发布依赖。
3. 样本必须明确区分顶层窗口、独立对话框、附着父窗口的 sheet、菜单、同窗口 overlay。没有独立窗口 ID 的 sheet 不造一个 HWND，也不强行按顶层窗口激活。
4. 扩展来源合同，例如独立 Mac source、字段级能力/缺失原因、采样时间与一致性状态。必要时调整平台边界 DTO，不为满足 Windows 字段而捏造 owner、windowClass 或全局 z-order。Windows 来源与行为继续保留。
5. 使用现有稳定 Session/Surface 生命周期。若只能取得精确父子 AX 关系而不能取得全局堆叠证明，必须独立设计并审查该类别的准入条件；不把局部证据直接标成旧合同的全局 complete。
6. probe 保持只读：不点击、不输入、不前置、不批准权限、不自动关闭弹窗。设置 Abort、超时、枚举/输出上限、进程回收和结构化错误。只输出必要身份、角色、几何和关系，文本内容核验走独立的已授权路径。
7. 核对截图像素与 AX/窗口几何坐标系，测试 Retina、窗口移动和缩放；不能因 Windows 代码使用同一个 bounds 类型就假定语义一致。

自动验证：正常与不完整快照、权限拒绝、截断、身份冲突、读取过程中窗口关闭、焦点改变、PID/窗口标识复用、helper 超时/崩溃、Abort、畸形输出、缺 owner/z-order、缩放几何冲突；全部拒绝路径不得产生输入。

人工验证：由人打开/关闭菜单或 sheet，仅运行只读采样；确认 probe 自己不会切窗、关闭弹窗或输入。记录采样耗时、缺失字段和权限表现。

通过门槛：至少能为普通顶层窗口和 TextEdit 一类真实弹窗提供可复核的精确证据；其他类别明确标 unsupported/manual。若公开接口与 SDK 均无法可靠关联，不使用标题/位置兜底，停止该类别自动化，交付具体限制及 SDK 改进需求。阶段二只证明探针可用，不证明点击成功。

## 阶段三 接通跨窗口后的实际操作

主要范围：`app-runtime/computers.ts`、`computer-cua/window-contract.ts`、`cua-driver-computer.ts`、`window-relationship-probe.ts` 及对应测试，具体以阶段一结果裁剪。

- Mac probe 按平台与能力注入，Runtime 不直接调用本机 API；不影响 Windows 现有 producer，不在 Linux 启动 Mac helper。
- 明确 browser 起点、native 起点加 companion 两种装配。先解释已有 companion 隔离意图，再决定是否及如何注入；不简单删除 Windows 排除条件。
- 保留默认跨窗关闭。开启后模型只能用当前 Run 的授权 windowRef；窗口关闭、引用过期、未授权目标必须拒绝。
- 切换完成必须核实精确焦点、捕获新观察、推进 Surface 代次并失效旧坐标/审批/输入许可。原生窗口不得沿用浏览器 DOM；切回同一受管页后重新取得 DOM。
- 补真实 wrapper → Runtime → adapter 的跨包测试，覆盖 F014 修复，不能只用永远成功的 Computer 假对象。
- 普通 click/type 后 inventory 检查也要覆盖：没有弹窗不误报；确实缺少必要证据时明确暂停/失败，不通过关闭检查来达成绿灯。

人工验证任务：受管浏览器测试页读取一个合成编号 → 切到空白 TextEdit 输入一次单行编号 → 切回同一测试页读取另一编号。反向以 TextEdit 起点再做一次。

通过门槛：两种起点各连续完成 3 次独立 Run，无错窗/重复输入/旧 DOM；每次都核对实际屏幕与轨迹。另测主动抢焦点、目标关闭和过期引用，预期为安全拒绝，不能计入正向成功次数。首次失败先定位，不通过增加连续重试掩盖不稳定。

## 阶段四 弹窗出现和消失后的连续操作

主要范围：`window-root-projection.ts`、`transient-window-admission.ts`、`surface-registry.ts` 与 CUA reconciliation。AX 角色映射只是必要条件，不单独构成授权证据。

依次实现并独立验收：

1. 菜单：父窗口打开菜单，精确识别 child，Escape 关闭，重新观察父窗口，再做一次无风险操作。
2. 打开文件对话框：打开后确认归属，取消，不读取或选择私人文件；返回原父窗口。
3. TextEdit 保存 sheet：仅打开和取消。父窗口仍是 frontmost 时，不把焦点在 sheet 的输入发送给父编辑区。
4. 同窗口 overlay：只有精确 root/几何及生命周期证据时接入；无证据明确保持人工处理，不以 screenshot 猜测。

自动测试必须覆盖：child 出现、隐藏、真正消失、仍可见、同标识替换、新的 owned child、父窗口关闭、模态嵌套、权限失效、读取竞争。child 关闭后推进父代次、旧 child 引用失效；已经完成的 Escape 不重放。无能力和真实矛盾分别记录。

人工验收：观察焦点是否在正确弹窗，取消后是否回到原文档且内容不变；各支持类别 3 次。系统权限提示由人处理，不加入自动批准路径。任何一次把内容输入到父文档或其他窗口，立即停止本批验证。

通过门槛：每类支持弹窗都有完整父 → child → 父观察和动作证据，任务继续且正常 cleanup。未支持类别显示可理解的原因及已有人工处理入口；若产品入口缺失，补最小反馈，不无限循环请求补充信息。

## 阶段五 中文多行和限定保存

当前原生多行路径明确 Windows only；此阶段单独实现 Mac 能力，不能靠删除平台拒绝直接放行。

1. 使用新空白 TextEdit 文档，确认纯文本模式、唯一可编辑目标、当前 Surface 和精确焦点。评估 SDK 可验证输入与 AX 可读回路径；仅为实际支持的编辑器开启。
2. 测试中文、数字、标点、换行、空行及重复文本。输入后通过可读回内容与实际画面交叉核对；截图只能看到部分内容时，不声称全文一致。
3. 中途失焦、只输入一部分、不可读回都应保留 partial/unknown 并停止自动续写，不重新发送整段。不默认改用全局剪贴板粘贴，因为它引入额外隐私与恢复问题。
4. 输入成功后才测试保存：用户确认仓库外或约定的专用测试目录，使用唯一新文件名；路径和操作范围固定，不覆盖，不处理已有私人文档。
5. 保存后核对文件存在、文本内容及重新打开结果，区分换行编码与内容错误。取消保存时不得产生文件或丢失原文档内容。

人工核对文本示例：

```text
周末出行清单
日期：10月10日
预算：100元

物品：水、雨伞、充电器。
```

通过门槛：短中文多行 3 次、较长一屏以上文本 1 次、取消保存 1 次、唯一文件保存并重开 1 次。未知结果不能显示成功。若 Mac 输入不能获得可靠核验，明确保留辅助模式，T2/T3 自动完成仍不放行。

## 阶段六 手机完整任务和交付

先运行确定性本机测试，再调用主模型，最后实体手机。三层结果分别记账：

- 离线：fixture 验证合同、异常和不重放，不消费模型额度。
- 无模型实机：受控脚本通过生产 adapter 验证本机能力，仍是真实桌面操作，需测试预约和授权，不等于模型任务通过。
- 手机和主模型：真实配对、选模式、开启跨窗、创建 Run、结果交付。不用辅助工具替模型输入或切窗；发生人工干预单列 assisted。

首个完整任务使用本地合成信息页：读取三个清单项 → 切到 TextEdit 整理 → 手机追加“删除其中一项” → 保存为专用目录中的唯一新文件 → 返回浏览器 → 报告实际成果。之后再选一个公开网页做同类真实任务，避免先把外网变化混入窗口调试。

手机侧人工检查：开关和起点正确；审批与实际操作一致；任务显示未完成/部分完成/完成与文件结果一致；刷新不丢记录；另起一个短 Run 测停止，停止后不再发新输入，既有在途操作如实记录。

模型/API 验证规则：

1. 沿用最新已批准模型和额度，不因窗口测试随意切模型或增大超时。每批开始前记录请求数、最长等待、整体预算与停止条件。
2. 分开统计 probe、激活、截图/DOM、输入、模型首响应/总请求、Guard、人工等待和 cleanup，不能把总时长全部归给 API。
3. T023 同类最终请求超时若再现，保留已完成动作和实际成果证据，但完整 Run 不计通过；不重放输入。纯只读重试是否允许须依现有请求语义和独立审查决定。
4. 第一轮先用少量任务，确定性链路通过后再做两种起点各 3 次模型任务。遇到同一失败不连续消耗额度；修复后新建 Run 复测。

通过门槛：至少受管浏览器、TextEdit、支持的菜单/sheet 完整链路正常，两种起点各 3 次自然结束并产生正确成果；无模型任务不能替代此项。所有意外输入、错误窗口、未知副作用重放、旧授权复用均为阻断项。

## 验证矩阵和记录规范

| 场景 | 应有结果 | 失败时处理 |
| --- | --- | --- |
| 跨窗关闭的普通点击和输入 | 不触发 opt-in 异常，也不开放切窗 | 回归 F014，不强开权限 |
| browser 与 native/companion 双向往返 | 新焦点与新观察，原生无 DOM，回网页 DOM 刷新 | 分层定位装配、激活或证据 |
| 普通动作后无弹窗 | 可靠 inventory 下继续 | 不完整证据明确降级，不伪造 complete |
| 菜单或 sheet 出现和取消 | 正确 child 与父恢复、代次递增 | 拒绝旧引用，不重放关闭动作 |
| 失焦、过期引用、窗口关闭 | 输入前拒绝或未知后停止 | 保留事件并人工检查结果 |
| 权限撤销或 probe 超时 | 清晰错误、Abort 有效、helper 可回收 | 不扩大权限或无限等待 |
| 模型最终请求超时 | 如实未完成，保留已有成果 | 不重复 GUI，交 API 线处理 |
| 多行输入及保存 | 内容准确、唯一新文件、可重开 | partial/unknown，不覆盖原文件 |
| Retina、移动和缩放 | 坐标与身份重新验证 | 不沿用旧坐标；多屏未测单列 |

每条记录包含源码/构建/进程/页面版本、场景与初态、Run ID、本机脱敏日志索引、预期/实际、人工介入、耗时分项、终态与 cleanup。正向结果为 passed/failed/partial/blocked，负向测试需注明“按预期拒绝”。只有真实支持类别才列入支持清单。

性能先采基线再定阈值：probe、列窗、切窗各采至少 10 个样本，记录中位数、P95 和最大值；首轮作为诊断样本，不当作可靠性统计保证。若 probe 每轮产生秒级延迟，定位进程冷启动/AX 查询，评估持久只读 helper；不要以复用过期权限证据换速度。

## 分工和修改边界

沿用[三聊天分工](./a-line-three-thread-coordination-2026-10-03.md)：（8）唯一源码实施与离线回归，（10）预约环境、构建部署和实机证据，（6）独立审查与远端交付。并行只用于独立模块调查、测试设计或只读审查；同一文件一名写入者，共享 dist 和桌面操作串行。

建议交付切片：Mac probe 与来源合同 → 平台注入及跨窗操作 → 弹窗生命周期 → 多行与保存 → 手机反馈及验收文档。每片由独立审查者检查身份/权限/未知副作用和 Windows 回归；发现问题修复后复审。模型执行/审查人选按届时用户指定，不由此计划擅自启动子任务。
