# Computer Harness：项目交接入口

更新：2026-09-27。PR #15 已合并，手机界面已部署；真实任务与平台能力仍按独立证据判断。下一阶段统一由[完整产品待办与分工清单](./product-next-stage-task-list-2026-09-27.md)安排，尚未分配负责人。

## 1. 项目目标

构建可替换组件的 GUI Agent Harness：模型提出决策，Computer 后端操作环境，Runtime 维护观察、动作、任务、记忆、审批、用户控制和完整运行事实。产品覆盖日常桌面应用与网页，不局限于出行票务；出行任务只是目前的一个真实试验域。

Pi 式改造的重点是薄应用入口、明确组合根和可替换策略，而不是复制某个外部项目。分包为后续实验、个性化和受控自进化提供工程基础；当前没有自动修改、部署自身代码的自进化系统。

## 6. 后续路线与非当前承诺

本节保留方向概览；具体近期/随后/研究顺序、完整任务和验收标准以[下一阶段清单](./product-next-stage-task-list-2026-09-27.md)为准。语音基础链路已提升为近期候选，长期研究不因此全部提前。

1. **可靠性与体验**：窗口/输入/弹层、配置透明度、TUI/Web 可读性和可诊断性；小步实现、真实复测。
2. **受控效果实验**：冻结代码、任务和策略版本，分别比较 Planning、Context、Memory、Batch/Monitor 等，不一次改变全部变量。真实生活任务和 OSWorld 分工互补。
3. **个性化/无障碍**：用户可读、可撤销的偏好与界面配置；手机可作便利入口，但不能把大字页面等同于完成适老化。
4. **后续研究**：长期 Memory、Advisory/Execution Subagent、Sandbox/ExecutionEnvironment、后台任务、语音和受控自进化。仍在考虑范围，不是当前已实现模块。

自进化若推进，优先让候选策略在离线/开发集验证，再经审查和版本切换进入执行链；禁止模型直接绕过安全合同改写线上 Runtime。Jev 是否继续用于动作选择，必须重新证明实际收益，不能沿用已经撤下的 fast path 承诺。
