## 修复内容及生命周期

### P0：观察和执行使用相同指纹

`managed-browser-host.ts` 的点击及 select_option 执行校验改用与采集端一致的 input type 语义：input 缺省为 text、转小写；非 input 不计 type。保持角色、名称、位置和唯一性校验，不吞掉真正的 stale 拒绝。

回归不再依靠复制的 synthetic 点击指纹算法，而是使用生产观察脚本及 `domCandidateFingerprint` 的输出作为执行输入，覆盖缺省 type、大小写、非 input type 与真实变更。

### P0：原生点击恢复焦点，输入前再次验证

- 观察的 focused 同时要求页面拥有焦点，并检查控件所在 root 的 activeElement。
- 可编辑 DOM 控件（包括映射回 DOM 的 UIA 引用）先由 `validateClick` 只读验证唯一候选、指纹、位置与实际点击点遮挡，再通过既有前台原生点击通道派发一次点击。非输入控件保留原 DOM 路径。
- 原生点击沿用已有坐标转换、目标窗口、前台守卫及窗口变化处理；不将 CSS 坐标直接作为原生坐标。不先 DOM 点击再补点。
- 对越出 CSS 视口任意一边的可编辑控件，在原生点击前以 `DOM_CLICK_CLIPPED` 拒绝，要求滚动至完整可见后重新观察，避免原始 CSS 中心与裁切后物理中心不同。
- `expectedDomInput` 由已验证的点击目标或唯一已观察且聚焦的可编辑控件建立，供后续原生键盘输入的 `verifyFocus` 消费；观察刷新不自动清除绑定。身份或焦点不符时拒绝发送，结果未知不重放。
- 显式地址栏快捷键成功后才进入受限地址栏输入模式；只授权下一次文本派发，派发前即消费，退出操作也清除许可。没有可验证的页面输入目标，也没有显式地址栏输入路径时，不盲目发送文本。
- `ManagedCdpDomGroundingTransport` 必须代理新增验证方法；测试覆盖实际 `createTransport()` 接线，避免只在 mock 中存在能力。

此保护仍有“校验到原生派发之间焦点变化”的时间窗口，不能承诺原子输入或防御恶意页面。页面焦点成功也不等于已完成真实 Mac 验收。

### P1：工具批处理提示一致

Context 明确现有 Runtime 只支持 click、精确 CTRL+A 的 hotkey 与 type 的有限同控件批次。click_element、CMD/Meta+A 单独调用后观察；memory_get 等读取不得与依赖其结果的 GUI 动作混用。GLM 提示遵循 Context 明确允许的批次，不再无条件与之冲突。

本轮没有扩大 Runtime 批处理能力、关闭 Guard、提高 API 超时或增加动作自动重试。长任务收尾、无进展循环、API 分段时延仍按进度复核列为后续任务。
